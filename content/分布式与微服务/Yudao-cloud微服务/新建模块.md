# 新建模块

> **一句话概括**：新建一个业务模块就 5 步 —— 建**父模块**（`pom` 打包）→ 建 `-api` 子模块（给别的模块调用）→ 建 `-biz` 子模块（真正的业务代码）→ 写 Controller → 在 `yudao-server` 里引入。**每个业务模块都是"父子两层三件套"结构。**

**适合谁读**：第一次接芋道项目、要加新业务的人。
**怎么读**：照着做一遍就会。「一」的**为什么要分 api / biz**是本篇灵魂，「四」的 404 排查必看。

---

## 零、先建立整体印象：为什么每个模块要拆成 3 个 Maven 工程？

芋道的一个业务模块长这样：

```
yudao-module-demo/              ← ① 父模块（packaging = pom，纯目录，不放代码）
├── yudao-module-demo-api/      ← ② API 子模块（只放接口和常量，给别的模块引用）
└── yudao-module-demo-biz/      ← ③ BIZ 子模块（真正的业务实现：Controller/Service/Mapper）
```

### 为什么要这么拆？

**因为要控制依赖方向，防止模块之间互相乱引。**

```
❌ 如果不拆（只有一个模块）：
   crm 模块想调用 system 的用户信息
   → 只能引入整个 system 模块
   → 连带把 system 的 Controller、Mapper、DO 全暴露出去了
   → 别的模块可以随便 new 你的 Mapper，直接查你的表
   → 久而久之，模块耦合成一团，没法拆微服务

✅ 拆成 api + biz：
   crm 模块只引入 system-api（只有接口 + DTO）
   → 拿不到 Mapper，拿不到 DO
   → 只能老老实实调接口
   → 未来拆微服务，api 包直接变成 Feign 接口，零改动
```

💡 **一句话**：**`-api` 是"我能提供什么服务"的说明书，`-biz` 是"我怎么实现的"黑盒子。别人只能看说明书。**

对比一下现实：你去餐厅，看**菜单**（api）点菜，不会跑到**后厨**（biz）自己炒。

## 一、第 1 步：新建父模块 `yudao-module-demo`

### 操作步骤

1. IDEA：`File → New → Module`
2. 选择 **Maven** 类型 → `Next`
3. **父模块选 `yudao`**，名字填 `yudao-module-demo` → `Finish`
4. **删掉自动生成的 `src` 目录**（父模块不放代码）
5. 改 `pom.xml`

### pom.xml

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project ...>
    <parent>
        <artifactId>yudao</artifactId>
        <groupId>cn.iocoder.boot</groupId>
        <version>${revision}</version>          <!-- ① 统一版本变量 -->
    </parent>
    <modelVersion>4.0.0</modelVersion>

    <artifactId>yudao-module-demo</artifactId>
    <packaging>pom</packaging>                   <!-- ② 关键：父模块用 pom 打包 -->

    <name>${project.artifactId}</name>           <!-- ③ -->
    <description>
        demo 模块，主要实现 XXX、YYY、ZZZ 等功能。   <!-- ④ -->
    </description>
</project>
```

**四个要点**：

| # | 要点 | 说明 |
|---|---|---|
| ① | `version` 用 `${revision}` | 芋道用 Maven 的 CI-friendly 版本，**全项目统一版本号**，别写死 |
| ② | `packaging = pom` | 父模块只是个"文件夹"，不产 jar |
| ③ | `name` | 显示名 |
| ④ | `description` | 模块描述，写清楚这模块干嘛的 |

## 二、第 2 步：新建 `-api` 子模块

同样 `File → New → Module`，**父模块选 `yudao-module-demo`**，名字 `yudao-module-demo-api`。

### pom.xml

```xml
<project ...>
    <parent>
        <artifactId>yudao-module-demo</artifactId>   <!-- ← 父模块是 demo，不是 yudao -->
        <groupId>cn.iocoder.boot</groupId>
        <version>${revision}</version>
    </parent>
    <modelVersion>4.0.0</modelVersion>

    <artifactId>yudao-module-demo-api</artifactId>
    <packaging>jar</packaging>                        <!-- ← 子模块用 jar -->

    <name>${project.artifactId}</name>
    <description>demo 模块 API，暴露给其它模块调用</description>

    <dependencies>
        <!-- 只依赖 yudao-common，保持轻量 -->
        <dependency>
            <groupId>cn.iocoder.boot</groupId>
            <artifactId>yudao-common</artifactId>
        </dependency>
    </dependencies>
</project>
```

⚠️ **注意**：`-api` 模块**只依赖 `yudao-common`**，不放任何业务相关依赖。越轻越好。

### 包结构

```
cn.iocoder.yudao.module.demo
├── api/        ← 对外暴露的接口，如 DemoApi.java
└── enums/      ← 对外暴露的枚举、常量
```

**示例**：

```java
// api/DemoApi.java
public interface DemoApi {
    String getDemoName(Long id);
}

// enums/DemoStatusEnum.java
@AllArgsConstructor
@Getter
public enum DemoStatusEnum {
    ENABLE(1, "开启"),
    DISABLE(0, "关闭");
    private final Integer status;
    private final String name;
}
```

## 三、第 3 步：新建 `-biz` 子模块

父模块同样选 `yudao-module-demo`，名字 `yudao-module-demo-biz`。

### pom.xml

```xml
<project ...>
    <parent>
        <artifactId>yudao-module-demo</artifactId>
        <groupId>cn.iocoder.boot</groupId>
        <version>${revision}</version>
    </parent>
    <modelVersion>4.0.0</modelVersion>
    <packaging>jar</packaging>

    <artifactId>yudao-module-demo-biz</artifactId>
    <name>${project.artifactId}</name>
    <description>demo 模块，主要实现 XXX、YYY、ZZZ 等功能。</description>

    <dependencies>
        <!-- ① 依赖自己的 api 模块 -->
        <dependency>
            <groupId>cn.iocoder.boot</groupId>
            <artifactId>yudao-module-demo-api</artifactId>
            <version>${revision}</version>
        </dependency>

        <!-- ② Web 相关：Controller、统一响应、全局异常 -->
        <dependency>
            <groupId>cn.iocoder.boot</groupId>
            <artifactId>yudao-spring-boot-starter-web</artifactId>
        </dependency>

        <!-- ③ 安全相关：登录、权限 -->
        <dependency>
            <groupId>cn.iocoder.boot</groupId>
            <artifactId>yudao-spring-boot-starter-security</artifactId>
        </dependency>

        <!-- ④ DB 相关：MyBatis Plus、多数据源 -->
        <dependency>
            <groupId>cn.iocoder.boot</groupId>
            <artifactId>yudao-spring-boot-starter-mybatis</artifactId>
        </dependency>

        <!-- ⑤ 单元测试 -->
        <dependency>
            <groupId>cn.iocoder.boot</groupId>
            <artifactId>yudao-spring-boot-starter-test</artifactId>
            <scope>test</scope>
        </dependency>
    </dependencies>
</project>
```

### 包结构

```
cn.iocoder.yudao.module.demo
├── controller/
│   ├── admin/          ← 管理后台接口（自动加 /admin-api 前缀）
│   ├── app/            ← 用户 App 接口（自动加 /app-api 前缀）
│   └── vo/             ← ReqVO / RespVO
├── convert/            ← MapStruct 转换器（见 [[VO 对象转换、数据翻译]]）
├── dal/
│   ├── dataobject/     ← DO 实体
│   └── mysql/          ← Mapper
├── service/            ← Service 接口 + impl 实现
└── enums/              ← 业务枚举、错误码常量
```

✅ 改完 pom 后，**点 Maven 面板的刷新按钮**，让依赖生效。

## 四、第 4 步：写 RESTful API 接口

### 管理后台 Controller

```java
package cn.iocoder.yudao.module.demo.controller.admin;

@Tag(name = "管理后台 - Test")                 // Swagger 分组名
@RestController
@RequestMapping("/demo/test")                // ← /demo 是模块前缀，/test 是功能前缀
@Validated                                   // 开启参数校验
public class DemoTestController {

    @GetMapping("/get")
    @Operation(summary = "获取 test 信息")     // Swagger 接口名
    public CommonResult<String> get() {
        return success("true");
    }
}
```

### 用户 App Controller

```java
package cn.iocoder.yudao.module.demo.controller.app;

@Tag(name = "用户 App - Test")
@RestController
@RequestMapping("/demo/test")                // ← 路径一样！
@Validated
public class AppDemoTestController {          // ← 类名加 App 前缀

    @GetMapping("/get")
    @Operation(summary = "获取 test 信息")
    public CommonResult<String> get() {
        return success("true");
    }
}
```

### ❓ 两个接口路径都是 `/demo/test/get`，不会冲突吗？

**不会。** 因为芋道自动加前缀：

| 包 | 最终路径 |
|---|---|
| `controller.admin` | `/admin-api/demo/test/get` |
| `controller.app` | `/app-api/demo/test/get` |

💡 **为什么 App 的 Controller 要加 `App` 前缀？** 官方给了两个理由：
1. 一眼看出是管理后台还是用户 App
2. **避免 Spring Bean 名字冲突**（两个类都叫 `DemoTestController` 会报错）

## 五、第 5 步：引入模块并启动

**① 在 `yudao-server/pom.xml` 引入 biz 模块**

```xml
<dependency>
    <groupId>cn.iocoder.boot</groupId>
    <artifactId>yudao-module-demo-biz</artifactId>
    <version>${revision}</version>
</dependency>
```

点 Maven 刷新。

**② 启动 `YudaoServerApplication`**

**③ 打开 Swagger**：`http://127.0.0.1:48080/doc.html`

你会看到"管理后台 - Test"和"用户 App - Test"两个分组，可以直接调试。

## 六、⚠️ 访问接口返回 404？

**这是新建模块最常见的报错。**

**原因**：你的包名不在 Spring 的扫描路径里。

芋道默认只扫描：
```java
@SpringBootApplication(scanBasePackages = {
    "${yudao.info.base-package}.server",
    "${yudao.info.base-package}.module"        // 即 cn.iocoder.yudao.module
})
```

**检查**：你的包名是不是 `cn.iocoder.yudao.module.demo`？

**如果你的包名是自定义的**（比如 `com.xxx.demo`），要手动加进去：

```java
@SpringBootApplication(scanBasePackages = {
    "${yudao.info.base-package}.server",
    "${yudao.info.base-package}.module",
    "xxx.yyy.zzz"        // ← 你的包名
})
```

💡 **建议**：别自创包名，老老实实用 `cn.iocoder.yudao.module.xxx`，省事。

## 七、补充配置

### 7.1 Swagger 接口分组

想让新模块在 Swagger 里有独立分组，加一个 `GroupedOpenApi` Bean：

```java
@Configuration
public class DemoSwaggerConfiguration {

    @Bean
    public GroupedOpenApi demoGroupedOpenApi() {
        return GroupedOpenApi.builder()
                .group("demo")                                        // 分组名
                .packagesToScan("cn.iocoder.yudao.module.demo")       // 扫描的包
                .build();
    }
}
```

### 7.2 MyBatis SQL 日志

新模块的 Mapper 默认不打印 SQL。要开的话，在 `application.yaml` 加：

```yaml
logging:
  level:
    cn.iocoder.yudao.module.demo: debug      # ← 你的模块包名
```

或者更精确：

```yaml
logging:
  level:
    cn.iocoder.yudao.module.demo.dal.mysql: debug    # 只开 Mapper 包
```

## 九、一句话总结

**新建模块 = 父模块（pom）+ api 子模块（只放接口给外人用）+ biz 子模块（真正的实现）。拆 api/biz 是为了控制依赖方向 —— 别的模块只能依赖你的 api，碰不到你的 Mapper 和 DO，未来拆微服务零改动。包名必须用 `cn.iocoder.yudao.module.xxx`，否则接口 404。**

## 附录：常见报错速查

| 报错 | 原因 | 解决 |
|---|---|---|
| 接口 404 | 包名不在扫描路径 | 用 `cn.iocoder.yudao.module.xxx` 或加 `scanBasePackages` |
| Bean 名字冲突 | 两个 Controller 同名 | App 的加 `App` 前缀 |
| Maven 依赖找不到 | 没刷新 | 点 Maven 面板刷新 |
| `version` 报错 | 写死了版本号 | 改成 `${revision}` |
| 启动报 Bean 缺失 | pom 少了 starter | 检查 web/security/mybatis 三个 starter |
