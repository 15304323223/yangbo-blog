# 代码生成【单表】

> **一句话概括**：**在数据库里设计好表结构 → 导入代码生成器 → 一键生成 前后端代码 + 单元测试 + Swagger 文档 + 参数校验**，官方说能省掉 **80% 的开发任务**。三种模式：单表、树表、主子表。

**适合谁读**：所有用芋道做业务的人 —— **这是芋道最值钱的功能**。
**怎么读**：照着「二」的 4 步做一遍。「三」的收尾步骤别漏（很多人卡在这）。

---

## 零、先建立整体印象：为什么不手写 CRUD？

> 官方吐槽得很到位：*"大部分项目里，其实有很多代码是重复的，几乎每个模块都有 CRUD 增删改查的功能，而这些功能的实现代码往往是大同小异的。如果这些功能都要自己去手写，非常无聊枯燥，浪费时间且效率很低，还可能会写错。"*

**一个"用户组"功能要写多少代码？**

| 层 | 文件 |
|---|---|
| 后端 | DO、Mapper、Service 接口、ServiceImpl、Controller、3 个 VO、Convert、枚举、错误码 |
| 单测 | ServiceTest、H2 建表脚本、clean 脚本 |
| SQL | 菜单初始化 SQL |
| 前端 | index.vue、Form.vue、api 的 .ts |
| 文档 | Swagger 注解、参数校验注解 |

**加起来 20+ 个文件，手写至少半天，还容易写错。代码生成器 5 分钟搞定。**

### 三种模式

| 模式 | 场景 | 例子 |
|---|---|---|
| **单表**（本篇） | 最普通的列表 | 用户组、字典、通知公告 |
| **树表** | 有层级关系 | 部门、分类、菜单 |
| **主子表** | 一对多/一对一关联 | 订单+订单明细、学生+成绩 |

## 一、第 1 步：设计数据库表

以"用户组"为例：

```sql
CREATE TABLE `system_group` (
  `id`          bigint      NOT NULL AUTO_INCREMENT COMMENT '编号',
  `name`        varchar(255) NOT NULL                COMMENT '名字',
  `description` varchar(512) DEFAULT NULL            COMMENT '描述',
  `status`      tinyint     NOT NULL                COMMENT '状态',
  `creator`     varchar(64) DEFAULT ''              COMMENT '创建者',
  `create_time` datetime    NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updater`     varchar(64) DEFAULT ''              COMMENT '更新者',
  `update_time` datetime    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted`     bit(1)      NOT NULL DEFAULT b'0'   COMMENT '是否删除',
  `tenant_id`   bigint      NOT NULL DEFAULT '0'    COMMENT '租户编号',
  PRIMARY KEY (`id`) USING BTREE
) ENGINE=InnoDB COMMENT='用户组';
```

### 建表的 5 条规范 ⭐

| # | 规范 | 为什么 |
|---|---|---|
| ① | **表名前缀要和模块名一致** | 用户组在 `yudao-module-system`，所以叫 `system_group`。**代码生成器靠前缀判断该生成到哪个 Maven 模块** |
| ② | 主键用 **bigint 自增** | 芋道推荐（见 [[MyBatis 数据库]]） |
| ③ | **字段是否允许 NULL 要写对** | 生成器据此生成参数校验规则（`@NotNull` / `@NotEmpty`） |
| ④ | **注释要写清楚** | 生成器的字段名、页面 label、Swagger 描述全靠它 |
| ⑤ | **必须有 `creator`/`create_time`/`updater`/`update_time`/`deleted`** | 系统字段，`BaseDO` 需要。开了多租户还要加 `tenant_id` |

⚠️ **第 ④ 条最容易被忽略**：你不写注释，生成的页面上字段就显示成 `description` 而不是"描述"。**改注释比改代码快得多。**

## 二、第 2 步：代码生成（4 小步）

### 2.1 导入表

[基础设施 → 代码生成] → **[基于 DB 导入]** → 勾选 `system_group` → [确认]

> 底层实现：`CodegenBuilder` 类，自动解析表结构，生成默认配置。

### 2.2 编辑配置

点击 `system_group` 行的 **[编辑]**。

#### 【字段信息】逐个字段调

| 配置项 | 作用 |
|---|---|
| **插入** | 新增时，是否传这个字段 |
| **编辑** | 修改时，是否传这个字段 |
| **列表** | 表格里是否展示这一列 |
| **查询** | 搜索框是否支持按它查，以及查询条件是什么（=、LIKE、BETWEEN…） |
| **允许空** | 是否必填 → 生成 `@NotNull` / `@NotEmpty` 校验 |
| **显示类型** | 文本框 / 下拉框 / 单选框 / 复选框 / 日期 / 文本域 |
| **字典类型** | 显示类型是下拉框/单选/复选时，用哪个字典 |
| **示例** | Swagger 文档的 `example` |

**本例的改动**：
- `status` 字段 → 显示类型改成**【下拉框】**，字典类型选**【系统状态】**
- `description` 字段 → **取消【查询】**（描述太长，不适合搜）
- `id`/`name`/`description`/`status` → 填上**【示例】**值

#### 【生成信息】

| 配置项 | 作用 |
|---|---|
| **生成场景** | `管理后台` 或 `用户 App` —— 决定 Controller 放 `admin` 还是 `app` 包 |
| **上级菜单** | 管理后台场景需要选，比如【系统管理】 |
| **前端类型** | 见下表 |

**前端项目 → 前端类型的对应**：

| 前端项目 | 前端类型 |
|---|---|
| `yudao-ui-admin-vue2` | Vue2 Element UI 标准模版 |
| `yudao-ui-admin-vue3` | Vue3 Element Plus 标准模版 / **Vue3 Element Plus Schema 模版** |

💡 **偷懒技巧**：在 `application.yaml` 里配一个默认值，以后每次都省了：

```yaml
yudao:
  codegen:
    front-type: 3      # 默认 UI 模版，避免每次都选
```

> 官方原话：*"后端的 application.yaml 配置文件中的 yudao.codegen.front-type 配置项，设置默认的 UI 模版，避免每次都需要设置。"*

改完点 **[提交]**。

### 2.3 预览代码

点 **[预览]**，在线看生成的代码，检查是否符合预期。

💡 **这步别跳过** —— 花 30 秒扫一眼，能省掉后面调试半小时。

### 2.4 生成代码

点 **[生成代码]**，下载压缩包，解压。

> 底层实现：`CodegenEngine` 类，基于 **Velocity 模板引擎**生成。模板文件在 `resources/codegen` 目录。

💡 **想改生成的代码风格？** 直接改 `resources/codegen` 下的 `.vm` 模板文件 —— **这是芋道代码生成器最灵活的地方**。

## 三、第 3 步：把代码放进项目（别漏这几步！）

### 后端（5 步）

**① 复制后端代码到项目**（Controller / Service / Mapper / DO / VO / Convert 各就各位）

**② 处理错误码** ⚠️

生成包里有个 `ErrorCodeConstants.java_手动操作` 文件 —— **注意文件名就写着"手动操作"**。

把里面的错误码**复制到你模块的 `ErrorCodeConstants` 类里，并手动设置正确的错误码编号**，然后删掉这个文件。

```java
// 生成的是这样（编号是占位符，必须改）
ErrorCode GROUP_NOT_EXISTS = new ErrorCode(XXXXXXXXXX, "用户组不存在");

// 你要改成符合分段规则的（见 [[异常处理（错误码）]]）
ErrorCode GROUP_NOT_EXISTS = new ErrorCode(1001003001, "用户组不存在");
```

**③ 处理 H2 脚本** ⚠️

生成包里有 `h2.sql`：
- 把 **CREATE 语句**复制到模块的 `create_tables.sql`
- 把 **DELETE 语句**复制到模块的 `clean.sql`

> 用途：单元测试需要 H2 内存数据库，`create_tables.sql` 建表，`clean.sql` 每个测试方法跑完清数据（见 [[单元测试]]）。

然后运行 `GroupServiceImplTest`，应该全绿。

**④ 执行菜单 SQL**

用数据库工具运行生成的 `sql/sql.sql` —— **这是初始化菜单数据的**（不然前端看不到菜单）。

**⑤ 启动后端**

Debug 启动 `YudaoServerApplication`。通过 IDEA 的 [Actuator → Mappings] 能看到 `GroupController` 的接口已生效。

### 前端（3 步）

**① 复制前端代码到项目**

**② 重启前端 + 刷新菜单缓存** ⚠️

```bash
npm run dev
```

然后去 [系统管理 → 菜单管理] 点**【刷新菜单缓存】**。

> **为什么？** 因为前端会把菜单缓存在内存里。不刷新的话，新菜单出不来。**这是最常见的"我明明生成了但看不到菜单"的原因。**

**③ 打开 [系统管理 → 用户组管理]**，界面就出来了。

## 四、后续变更：改字段怎么办？

⚠️ **官方明确建议：不要用代码生成器重新生成，直接改代码。**

> *"随着业务的发展，已经生成代码的功能需要变更……此时不建议使用代码生成器，而是直接修改已经生成的代码。"*

**比如 `system_group` 要加一个 `category` 字段**：

1. **数据库**：`ALTER TABLE system_group ADD COLUMN category varchar(64) ...`
2. **后端**：改 3 个类
   - `GroupDO` 加 `category` 字段
   - `GroupSaveReqVO` 加 `category` 字段
   - `GroupRespVO` 加 `category` 字段
3. **前端**：改 `index.vue`（列表加一列）和 `Form.vue`（表单加一项）
4. **重新编译启动**

💡 **为什么不建议重新生成？** 因为你很可能已经在生成的代码上做了业务改造，重新生成会**覆盖掉你的改动**。

## 五、❓ 为什么要分 3 个 VO 类？

生成出来的 VO 有 3 个：`XxxSaveReqVO`、`XxxRespVO`、`XxxPageReqVO`。

> 官方给出的理由：*"总体大家倾向拆分成三个 VO 类，因为这样更加清晰，而且也不会增加太多的维护工作量。"*

**为什么不把 SaveReqVO 和 RespVO 合并成一个？** 官方给了两条：

**① 字段天然不一样**

```
新增/修改时：不传 createTime、creator（这些是系统生成的）
响应时：     要返回 createTime、creator（前端要显示"创建时间"）
```

合并的话，`createTime` 该不该有？加校验注解还是不加？**两难。**

**② 维护成本其实差不多**

> *"一旦 VO 和 DO 拆分开后，调整字段时，例如说新增一个 xxx 字段，两个 VO 的修改成本，和一个 VO 实际是差不多的。"*

💡 **说人话**：新增字段时，你要改 DO + SaveReqVO + RespVO = 3 处；合并成 1 个 VO 就是改 DO + 1 个 VO = 2 处。**省 1 处，但换来一堆字段职责混乱，不划算。**

三个 VO 的职责：

| VO | 用途 | 特点 |
|---|---|---|
| `XxxSaveReqVO` | 新增/修改的**入参** | 没有 id（新增时）、没有 createTime |
| `XxxPageReqVO` | 分页查询的**入参** | 继承 `PageParam`，有查询条件 |
| `XxxRespVO` | **出参** | 有 id、createTime，可能还有翻译字段 |

## 六、踩坑清单

| # | 坑 | 症状 | 解法 |
|---|---|---|---|
| 1 | **表名前缀和模块名不一致** | 生成到错误的模块，或找不到模块 | 表名用 `模块名_` 开头 |
| 2 | **忘了执行菜单 SQL** | 前端看不到菜单 | 运行 `sql/sql.sql` |
| 3 | **没刷新菜单缓存** | 菜单还是不显示 | [菜单管理] → 刷新菜单缓存 |
| 4 | **错误码编号没改** | 编译时报错或错误码冲突 | 手动改成符合分段规则的编号 |
| 5 | **H2 脚本没复制** | 单元测试跑挂 | 复制 CREATE 和 DELETE 语句 |
| 6 | 字段没写注释 | 页面显示字段名而不是中文 | 补注释后重新导入 |
| 7 | `deleted` / `tenant_id` 没加 | 逻辑删除、多租户失效 | 建表时补上（见 [[MyBatis 数据库]]） |
| 8 | 重新生成覆盖了改动 | 自己写的业务代码没了 | 后续变更直接改代码，不重新生成 |
| 9 | 前端类型选错 | 前端代码用不了 | 按实际前端项目选 |
| 10 | 生成场景选错 | Controller 放错包 | 管理后台选"管理后台"，App 选"用户 App" |

---

## 七、一句话总结

**代码生成 4 步：建表（前缀=模块名、注释写全、含 5 个系统字段）→ 导入 → 调配置（字段的列表/查询/字典/示例 + 上级菜单 + 前端类型）→ 生成。收尾别漏 4 件事：错误码手动编号、H2 脚本复制、菜单 SQL 执行、前端刷新菜单缓存。后续加字段直接改代码，别重新生成。**
