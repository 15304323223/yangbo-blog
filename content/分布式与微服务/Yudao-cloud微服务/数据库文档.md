# 数据库文档

> **一句话概括**：芋道集成 **Screw** 工具，自动从数据库读取表结构，生成一份**带注释、带字段说明的在线数据库文档** —— 不用手动维护 Word/Excel 了，改完表结构刷新页面就同步。

**适合谁读**：要出数据库设计文档、要给新人讲表结构的人。
**怎么读**：本篇很短，看完就能用。

---

## 零、先建立整体印象：为什么不用 Word/Excel？

传统做法：

```
① 数据库改了字段
② 打开 Word，找到对应表，手动改
③ 忘了改 → 文档和数据库不一致 → 新人被坑
④ 下次又改 → 重复步骤 ②
```

芋道的做法：

```
① 数据库改了字段
② 刷新 [基础设施 → 数据库文档] 页面
③ 自动同步 ✅
```

💡 **核心原理**：Screw 直接连数据库读 `INFORMATION_SCHEMA`，实时拿到最新的表结构、字段类型、注释。**数据库就是文档的唯一来源。**

### 1.2 背后的实现

**后端**：`yudao-module-infra` 的 `DatabaseDocController`，基于 [Screw](https://github.com/pingfangushi/screw) 实现。

**Screw 是什么？**

> 一个 Java 小工具，连上数据库 → 读 `INFORMATION_SCHEMA.TABLES` 和 `COLUMNS` → 生成 HTML/Markdown/Word 格式的文档。

**核心逻辑**（简化版）：

```java
// DatabaseDocController.java
@GetMapping("/get")
public CommonResult<String> get() {
    // ① 配置数据源（用当前项目的数据源）
    DataSourceConfig dataSourceConfig = new DataSourceConfig();
    dataSourceConfig.setUrl(dataSourceProperties.getUrl());
    dataSourceConfig.setUsername(dataSourceProperties.getUsername());
    dataSourceConfig.setPassword(dataSourceProperties.getPassword());

    // ② 配置文档（HTML 格式）
    EngineConfig engineConfig = EngineConfig.builder()
        .fileOutputDir(fileOutputDir)
        .produceType(EngineFileType.HTML)
        .build();

    // ③ 执行生成
    new DocumentationExecute(dataSourceConfig).execute();

    // ④ 返回 HTML 内容
    return success(FileUtil.readUtf8String(htmlFile));
}
```

### 1.3 文档质量取决于什么？

**数据库注释写得好不好。**

```sql
-- ✅ 好的注释：生成器能直接拿来用
CREATE TABLE `system_user` (
  `id`       bigint      NOT NULL AUTO_INCREMENT COMMENT '编号',
  `username` varchar(30) NOT NULL                COMMENT '用户名',
  `status`   tinyint     NOT NULL DEFAULT '0'    COMMENT '状态（0-禁用，1-开启）',
  PRIMARY KEY (`id`)
) COMMENT='用户信息表';

-- ❌ 差的注释：生成出来的文档没法看
CREATE TABLE `system_user` (
  `id`       bigint      NOT NULL AUTO_INCREMENT,   -- 没注释
  `username` varchar(30) NOT NULL,                   -- 没注释
  `status`   tinyint     NOT NULL DEFAULT '0'        -- 没注释
);                                                  -- 表也没注释
```

💡 **所以建表时写注释不是"锦上添花"，是"刚需"** —— 它同时影响：
1. 代码生成器的字段名和页面 label（见 [[代码生成【单表】]]）
2. Swagger 文档的描述
3. 数据库文档的可读性

## 二、进阶：导出离线文档

Screw 除了生成 HTML，还支持导出 **Markdown** 和 **Word**。

如果你需要一份离线文档（比如给客户、给评审），可以：

```java
// 改 EngineFileType
EngineConfig engineConfig = EngineConfig.builder()
    .fileOutputDir("/tmp/db-doc/")
    .produceType(EngineFileType.WORD)    // ← 改成 WORD
    .build();
```

或者在芋道的 `DatabaseDocController` 里加一个新的接口，返回 Word 文件下载。

---

## 三、一句话总结

**数据库文档 = Screw 实时读数据库结构 + 生成 HTML 页面。文档质量完全取决于建表时写的注释，所以建表一定要写 COMMENT。改完表结构刷新页面就同步，不用手动维护。**
