# 三方登录（微信 / 钉钉 / 企业微信）

> **一句话概括**：让用户用钉钉、企业微信、公众号扫码登录你的系统。芋道用 **JustAuth** 组件对接，支持"**快捷登录**"（已绑定直接进）和"**绑定登录**"（未绑定先绑账号）两种流程。

---

## 零、先建立整体印象：用支付宝登录别的 App

> 🧒 **费曼第 1 段 · 5 岁小孩也能懂**

你下载了一个新 App，注册时要填手机号、收验证码、设密码 —— 麻烦。

App 说："你可以**用微信直接登录**。"

点了之后：
1. 跳到微信，微信问你"是否授权这个 App 获取你的昵称头像？"
2. 你点「同意」
3. 回到 App，**已经登录了**，头像昵称都同步过来了

你**没有**把微信密码告诉这个 App —— 微信只是发了一张"临时凭证"给 App。

芋道支持的三方平台：

| 端 | 支持的三方 |
|---|---|
| **管理后台** | 企业微信、阿里钉钉 |
| **用户 App** | 微信公众号、微信小程序 |

## 一、原理篇

### 1.1 两张核心表 ⭐

| 表 | 存什么 |
|---|---|
| `system_social_user` | **三方用户**信息（openid、昵称、头像、type 平台类型） |
| `system_social_user_bind` | **绑定关系**（三方用户 ↔ 本系统 User） |

**核心逻辑**：

```
三方登录成功
    │
    ▼
查 system_social_user_bind 有没有绑定记录
    │
    ├── 有 → 快捷登录（直接进入系统）
    │
    └── 无 → ❌ 报"未绑定账号，需要进行绑定"
              → 用户输入账号密码 → 绑定登录 → 写入 bind 表
              → 下次就能快捷登录了
```

### 1.2 为什么第一次要绑定？

因为三方用户（钉钉账号）和本系统用户（AdminUser）**是两套账号体系**。系统不知道"这个钉钉用户 = 哪个系统用户"，所以必须让用户**输一次账号密码**来建立关联。

**关联建立后**，下次扫码就直接登录，不用再输密码了。

### 1.3 JustAuth 组件

芋道用 **JustAuth**（国产开源）对接三方平台。它的价值：**统一了国内外几十家三方平台的 OAuth 流程**，接新平台只需加配置。

## 二、应用篇

### 2.1 接口一览

| 接口 | 作用 |
|---|---|
| `/admin-api/system/auth/social-auth-redirect` | 获取三方平台的**授权跳转地址** |
| `/admin-api/system/auth/social-login` | 用 code 授权码**快捷登录** |
| `/admin-api/system/auth/login` + social 参数 | **绑定登录**（账号密码 + 三方信息） |
| `/app-api/member/auth/weixin-mini-app-login` | 微信小程序**一键登录** |

### 2.2 流程一：绑定登录（首次）

```
① 访问登录页，点击「钉钉」
        │
        ▼
② 调 social-auth-redirect → 拿到钉钉授权地址 → 跳转
        │
        ▼
③ 钉钉扫码授权 → 回调 /social-login 页面
        │
        ▼
④ 调 social-login 接口 → ❌ "未绑定账号，需要进行绑定"
        │
        ▼
⑤ 用户输入账号密码，点「提交」
   （调 login 接口，额外带 socialType + socialCode + socialState）
        │
        ▼
⑥ 绑定成功 → 进入首页 → 下次可快捷登录
```

### 2.3 流程二：快捷登录（已绑定）

```
① 访问登录页，点击「钉钉」
        │
        ▼
② 调 social-auth-redirect → 跳转钉钉授权
        │
        ▼
③ 扫码授权 → 回调 /social-login
        │
        ▼
④ 调 social-login 接口 → ✅ 有绑定记录 → 直接进首页
```

### 2.4 绑定与解绑

用户可在【个人中心 → 社交信息】里管理三方账号的绑定/解绑。

## 三、配置篇

### 3.1 方式一：配置文件

```yaml
# application-{env}.yaml
justauth:
  enabled: true
  type:
    DINGTALK:
      client-id: your-appkey
      client-secret: your-appsecret
      redirect-uri: http://127.0.0.1:1024/social-login
    WECHAT_ENTERPRISE:
      client-id: your-corpid
      client-secret: your-corpsecret
      redirect-uri: http://127.0.0.1:1024/social-login
```

### 3.2 方式二：数据库配置（推荐）⭐

表 `system_social_client`，在【系统管理 → 三方登录 → 三方应用】菜单配置。

```sql
CREATE TABLE `system_social_client` (
  `id`            bigint       NOT NULL AUTO_INCREMENT COMMENT '编号',
  `name`          varchar(255) NOT NULL COMMENT '应用名',
  `status`        tinyint      NOT NULL COMMENT '状态',
  -- JustAuth 配置项
  `social_type`   tinyint      NOT NULL COMMENT '社交平台的类型',
  `client_id`     varchar(255) NOT NULL COMMENT '客户端编号',
  `client_secret` varchar(255) NOT NULL COMMENT '客户端密钥',
  `agent_id`      varchar(255) DEFAULT NULL COMMENT '代理编号（企业微信用）',
  -- 两个隔离维度
  `tenant_id`     bigint       NOT NULL DEFAULT '0' COMMENT '租户编号',
  `user_type`     tinyint      NOT NULL COMMENT '用户类型',
  PRIMARY KEY (`id`)
) COMMENT='社交客户端表';
```

**两个关键设计**：

| 字段 | 作用 |
|---|---|
| `tenant_id` | **多租户隔离**：不同租户用不同的三方应用配置 |
| `user_type` | **用户类型隔离**：管理员和会员用不同的三方应用配置 |

> ⚠️ **优先级**：**数据库配置 > 配置文件**！代码见 `SocialClientServiceImpl#buildAuthRequest(...)`。

> 💡 **官方说明的局限**：
> 目前**不支持**"租户 + 用户类型 + 社交平台"三个维度的**多套配置**（比如同一租户下管理员和会员各配两套）。
> 需要的话要自己改造：加一个 `application` 应用字段，前端调用时传过来。

## 四、进阶篇

### 4.1 三方登录的两种方式对比

| | 后台（企业微信/钉钉） | App（微信） |
|---|---|---|
| 授权方式 | 扫码 | 扫码 / 小程序一键登录 |
| 用户类型 | AdminUser（管理员） | MemberUser（会员） |
| 自动注册 | ❌ 必须绑定已有账号 | ✅ 可自动创建会员 |

### 4.2 小程序一键登录（体验最好）⭐

```java
@PostMapping("/weixin-mini-app-login")
public CommonResult<AppAuthLoginRespVO> weixinMiniAppLogin(
        @RequestBody @Valid AppAuthWeixinMiniAppLoginReqVO reqVO) {
    return success(authService.weixinMiniAppLogin(reqVO));
}
```

入参两个 code：

| 参数 | 换取什么 |
|---|---|
| `loginCode` | `openid`（用户在小程序内的唯一身份） |
| `phoneCode` | **手机号**（微信绑定的手机号） |

**为什么体验最好？** 用户不用输手机号、不用等验证码，点一下就登录。这是小程序的主流方案。

### 4.3 生产环境 6 个坑

| 坑 | 现象 | 解决 |
|---|---|---|
| **回调地址不对** | 三方平台报 `redirect_uri 错误` | 三方平台后台配置的**回调域名**必须包含 `/social-login` 和 `/user/profile` |
| **client_secret 泄露** | 别人冒充你的应用 | 只存后端/数据库，**绝不写进前端代码** |
| **没处理"未绑定"分支** | 用户卡在报错页 | 前端要捕获错误码，跳到绑定页 |
| **state 参数没校验** | **CSRF 攻击** | 必须校验 `state`（芋道的 `socialState` 参数） |
| **绑定关系被重复创建** | 一个三方账号绑了多个系统账号 | `system_social_user_bind` 加唯一索引 |
| **解绑后无法登录** | 用户解绑了唯一登录方式 | 解绑前检查是否还有其他登录方式 |

> ⚠️ **state 参数很重要**：三方登录是 CSRF 攻击的重灾区。攻击者可以诱导用户用**攻击者自己的三方账号**登录，从而劫持会话。必须校验 state。

### 4.4 三方登录 vs OAuth 2.0 SSO 的区别

| | 三方登录（本篇） | OAuth 2.0 SSO（[[OAuth 2.0（SSO 单点登录）]]） |
|---|---|---|
| 谁是谁的"第三方" | **芋道是接入方**，微信/钉钉是授权方 | **芋道是授权方**，别的系统接入芋道 |
| 方向 | 芋道 → 微信（我去借账号） | 别的系统 → 芋道（别人来借账号） |
| 用户 | 我的用户用微信登录 | 我的用户可以让别的系统登录 |

> 💡 记住：**三方登录你是"乙方"，SSO 你是"甲方"**。芋道两个方向都实现了，这是它强大之处。

## 五、一句话总结

| 问题 | 答案 |
|---|---|
| 支持哪些三方 | 后台：企业微信、钉钉；App：微信公众号、小程序 |
| 用什么组件 | **JustAuth**（统一各家 OAuth 流程） |
| 两种流程 | **快捷登录**（已绑定）/ **绑定登录**（首次要输密码） |
| 两张表 | `system_social_user`（三方用户）+ `system_social_user_bind`（绑定关系） |
| 配置在哪 | 数据库 `system_social_client`（**优先级高于配置文件**） |
| 支持多租户 | ✅ 靠 `tenant_id` + `user_type` 隔离 |
| 最大坑 | 回调地址配置 + **state 参数校验**（防 CSRF） |
