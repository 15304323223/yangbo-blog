# 代码生成【主子表】

> **一句话概括**：主子表 = **一张主表 + 多张子表**，通过子表的外键（如 `student_id`）关联。生成器里把主表设成**【主表（标准/内嵌/ERP 模式）】**、把每张子表设成**【子表】并指明关联字段和关系** —— 就这一个动作，前后端联动的增删改查全出来了。

**前置阅读**：[[代码生成【单表】]] —— 重复部分本篇不赘述。

---

## 零、先建立整体印象：什么是主子表？

> 官方定义：*"主子表，指的是一个主表，被多个子表所关联，关联的关系是一对一或一对多。"*

**例子**：主表是【学生】，子表可以是：

| 子表 | 关系 | 说明 |
|---|---|---|
| 【成绩】 | **一对多** | 一个学生可以有多个成绩（语文、数学、英语…） |
| 【班级】 | **一对一** | 一个学生只能有一个班级 |

**更常见的业务例子**：

| 主表 | 子表 | 关系 |
|---|---|---|
| 订单 `order` | 订单明细 `order_item` | 一对多 |
| 合同 | 合同条款 / 合同附件 | 一对多 |
| 学生 | 成绩 / 班级 | 一对多 / 一对一 |
| 报价单 | 报价明细 | 一对多 |
| 文章 | 标签 | 一对多 |

💡 **一句话判断**：**"一个 X 有多个 Y，Y 不能独立存在" → 就是主子表。**

---

## 一、三种主子表模式 ⭐

芋道提供 **3 种交互模式**，这是本篇最重要的概念 —— **选错模式，生成的页面完全不是你想要的**。

### 0.1 标准模式 ⭐（最常用）

> 对应菜单：[基础设施 → 代码生成案例 → 主子表（标准）]

**特点**：**新增和修改时，主表和子表在【一个弹窗表单】里，一起提交。**

```
┌────────── 新增学生 ──────────┐
│ 姓名：[张三        ]          │  ← 主表字段
│ 生日：[2020-01-01  ]          │
│ 简介：[............]          │
│                              │
│ ── 课程（子表）─────────────  │
│ | 语文 | 95  | [删除] |      │  ← 子表：可动态增删行
│ | 数学 | 88  | [删除] |      │
│ [+ 添加课程]                  │
│                              │
│      [取消]  [确定]           │  ← 一次性提交全部
└──────────────────────────────┘
```

**适合**：子表行数不多（几条到十几条），希望一屏搞定。
**典型**：订单 + 订单明细、学生 + 成绩。

### 0.2 内嵌模式

> 对应菜单：[基础设施 → 代码生成案例 → 主子表（内嵌）]

**特点**：在标准模式基础上，**列表页内嵌显示子表的列表**。

```
┌─ 学生列表 ────────────────────────────┐
│ ▼ 张三   男   2020-01-01              │  ← 展开箭头
│     ┌─ 课程 ─────────────────┐        │
│     │ 语文  95              │        │  ← 内嵌的子表
│     │ 数学  88              │        │
│     └───────────────────────┘        │
│ ▶ 李四   女   2020-03-15              │  ← 未展开
└──────────────────────────────────────┘
```

**适合**：想在主列表里就看到明细，不想到详情页。
**典型**：订单列表直接看有哪些商品。

### 0.3 ERP 模式

> 对应菜单：[基础设施 → 代码生成案例 → 主子表（ERP）]

**特点**：**主表和子表各自独立的列表，各自独立的表单。**

```
学生管理（主表列表）
┌────────────────────────────┐
│ 张三  [编辑] [删除] [管理课程] │  ← 点"管理课程"进入子表
│ 李四  [编辑] [删除] [管理课程] │
└────────────────────────────┘
            ↓ 点击
课程管理（子表列表，独立页面）
┌────────────────────────────┐
│ 语文  95  [编辑] [删除]      │
│ 数学  88  [编辑] [删除]      │
│        [+ 新增课程]          │
└────────────────────────────┘
```

**适合**：子表数据量大、字段多、需要独立管理。
**典型**：ERP 系统（所以叫 ERP 模式）、商品管理 + SKU 管理。

### 三种模式对比

| | 标准 | 内嵌 | ERP |
|---|---|---|---|
| 新增/修改 | **一个弹窗，主子一起提交** | 同标准 | **各自独立表单** |
| 列表 | 只有主表 | **主表内嵌子表** | **各自独立列表** |
| 子表数据量 | 少（几条） | 少 | **多** |
| 典型场景 | 订单+明细 | 快速查看明细 | 商品+SKU |
| 前端支持 | Vue3 ✅ | Vue3 ✅ | Vue3 ✅ |

⚠️ **官方提醒**：*"目前只有 yudao-ui-admin-vue3 支持主子表，yudao-ui-admin-vue2、yudao-ui-admin-vben 正在适配中！"*

## 二、第 1 步：设计表结构（1 主 + 2 子）

### ① 主表：学生表

```sql
CREATE TABLE `system_student` (
  `id`          bigint       NOT NULL AUTO_INCREMENT COMMENT '编号',
  `name`        varchar(100) NOT NULL DEFAULT ''     COMMENT '名字',
  `birthday`    datetime     NOT NULL                COMMENT '出生日期',
  `description` varchar(255) NOT NULL                COMMENT '简介',
  `creator`     varchar(64)  DEFAULT ''              COMMENT '创建者',
  `create_time` datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updater`     varchar(64)  DEFAULT ''              COMMENT '更新者',
  `update_time` datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted`     bit(1)       NOT NULL DEFAULT b'0'   COMMENT '是否删除',
  `tenant_id`   bigint       NOT NULL DEFAULT '0'    COMMENT '租户编号',
  PRIMARY KEY (`id`) USING BTREE
) ENGINE=InnoDB COMMENT='学生表';
```

### ② 子表 1：学生课程表（**一对多**）

```sql
CREATE TABLE `system_student_course` (
  `id`         bigint       NOT NULL AUTO_INCREMENT COMMENT '编号',
  `student_id` bigint       NOT NULL                COMMENT '学生编号',   -- ⭐ 外键
  `name`       varchar(100) NOT NULL DEFAULT ''     COMMENT '名字',
  `score`      tinyint      NOT NULL                COMMENT '分数',
  -- ... 省略 5 个系统字段 + tenant_id
  PRIMARY KEY (`id`) USING BTREE
) ENGINE=InnoDB COMMENT='学生课程表';
```

> *"它和主表的关系是一对多，一个学生可以有多个课程，通过 `student_id` 字段进行关联。"*

### ③ 子表 2：学生班级表（**一对一**）

```sql
CREATE TABLE `system_student_grade` (
  `id`         bigint       NOT NULL AUTO_INCREMENT COMMENT '编号',
  `student_id` bigint       NOT NULL                COMMENT '学生编号',   -- ⭐ 外键
  `name`       varchar(100) NOT NULL DEFAULT ''     COMMENT '名字',
  `teacher`    varchar(255) NOT NULL                COMMENT '班主任',
  -- ... 省略 5 个系统字段 + tenant_id
  PRIMARY KEY (`id`) USING BTREE
) ENGINE=InnoDB COMMENT='学生班级表';
```

> *"它和主表的关系是一对一，一个学生只能有一个班级，通过 `student_id` 字段进行关联。"*

### 建表要点

| # | 要点 | 说明 |
|---|---|---|
| ① | **子表必须有外键字段** | 本例是 `student_id`，指向主表 `id` |
| ② | **三张表前缀一致** | 都是 `system_`，才能生成到同一个模块 |
| ③ | **子表也要有 5 个系统字段** | `creator`/`create_time`/`updater`/`update_time`/`deleted` |
| ④ | **一对一关系建议加唯一索引** | `UNIQUE KEY uk_student_id (student_id, deleted)` |
| ⑤ | 外键字段注释写清楚 | 生成的页面 label 靠它 |

## 三、第 2 步：代码生成

### 3.1 导入表

[基础设施 → 代码生成] → **[基于 DB 导入]** → **同时勾选 3 张表** → [确认]

⚠️ 三张表都要导进来。

### 3.2 编辑主表配置 🔥

点击 `system_student` 行的 **[编辑]**：

| 配置项 | 值 |
|---|---|
| **【生成模版】** | **【主表（标准模式）】** ← 🔥 最关键 |
| 【上级菜单】 | 系统管理 |
| 【前端类型】 | Vue3 Element Plus 标准模版 |

### 3.3 编辑子表配置 🔥

**子表 1：点击 `system_student_course` 行的 [编辑]**

| 配置项 | 值 |
|---|---|
| **【生成模版】** | **【子表】** ← 🔥 最关键 |
| 【业务名】 | `student`（**和主表保持一致**） |
| 【关联的主表】 | `system_student` |
| 【子表关联的字段】 | `student_id` |
| 【关联关系】 | **一对多** |

**子表 2：点击 `system_student_grade` 行的 [编辑]**

| 配置项 | 值 |
|---|---|
| 【生成模版】 | 【子表】 |
| 【业务名】 | `student` |
| 【关联的主表】 | `system_student` |
| 【子表关联的字段】 | `student_id` |
| 【关联关系】 | **一对一** |

⚠️ **三个最容易漏的点**：
1. 主表的模版要选**【主表（标准模式）】**（不是默认的"单表"）
2. 子表的模版要选**【子表】**
3. 子表的**【业务名】改成和主表一样**（`student`），否则生成的类名和主表不统一

### 3.4 预览 + 生成

点 `system_student` 行的 **[预览]** → 检查 → **[生成]**

> ⚠️ **注意：只需要生成主表！** 子表的代码会跟着主表一起生成出来（因为配置了关联关系）。

## 四、生成了什么不一样的？

### 后端

**① 保存 VO 里嵌套了子表列表**

```java
@Data
public class StudentSaveReqVO {

    @NotNull(message = "编号不能为空")
    private Long id;

    @NotEmpty(message = "名字不能为空")
    private String name;

    // ... 主表字段

    /** 课程列表（一对多子表） */
    private List<Course> courses;

    /** 班级（一对一子表） */
    private Grade grade;

    @Data
    public static class Course {
        private Long id;
        private String name;
        private Integer score;
    }

    @Data
    public static class Grade {
        private String name;
        private String teacher;
    }
}
```

**② Service 里用事务保证主子表一起保存** ⭐

```java
@Override
@Transactional(rollbackFor = Exception.class)     // ← 必须！
public Long createStudent(StudentSaveReqVO reqVO) {
    // ① 保存主表
    StudentDO student = BeanUtils.toBean(reqVO, StudentDO.class);
    studentMapper.insert(student);

    // ② 保存一对多的子表（课程）
    if (CollUtil.isNotEmpty(reqVO.getCourses())) {
        List<StudentCourseDO> courses = reqVO.getCourses().stream()
            .map(c -> {
                StudentCourseDO course = BeanUtils.toBean(c, StudentCourseDO.class);
                course.setStudentId(student.getId());      // ← 设置外键
                return course;
            })
            .collect(Collectors.toList());
        studentCourseMapper.insertBatch(courses);          // 批量插入
    }

    // ③ 保存一对一的子表（班级）
    if (reqVO.getGrade() != null) {
        StudentGradeDO grade = BeanUtils.toBean(reqVO.getGrade(), StudentGradeDO.class);
        grade.setStudentId(student.getId());
        studentGradeMapper.insert(grade);
    }

    return student.getId();
}
```

⚠️ **`@Transactional` 是必须的** —— 主表存了但子表失败，会留下脏数据。

**③ 修改时先删后插（子表的标准做法）**

```java
@Override
@Transactional(rollbackFor = Exception.class)
public void updateStudent(StudentSaveReqVO reqVO) {
    // ① 更新主表
    studentMapper.updateById(BeanUtils.toBean(reqVO, StudentDO.class));

    // ② 子表：先删掉旧的，再插入新的
    studentCourseMapper.deleteByStudentId(reqVO.getId());
    // ③ 重新插入
    insertCourses(reqVO.getId(), reqVO.getCourses());
}
```

💡 **为什么"先删后插"而不是"比对差异"？**

子表行可能新增、删除、修改，还要处理顺序 —— **比对差异的逻辑复杂度是指数级的**。而子表通常就几行，**全删重插简单可靠**。

⚠️ **代价**：子表的 `id` 会变。如果别的表引用了子表 id，就不能这么做。

**④ 查询时组装子表数据**

```java
@Override
public StudentRespVO getStudent(Long id) {
    StudentDO student = studentMapper.selectById(id);

    // 查一对多子表
    List<StudentCourseDO> courses = studentCourseMapper.selectListByStudentId(id);
    // 查一对一子表
    StudentGradeDO grade = studentGradeMapper.selectByStudentId(id);

    // 组装
    StudentRespVO respVO = BeanUtils.toBean(student, StudentRespVO.class);
    respVO.setCourses(BeanUtils.toBean(courses, Course.class));
    respVO.setGrade(BeanUtils.toBean(grade, Grade.class));
    return respVO;
}
```

⚠️ **列表查询时别这么做** —— 会 N+1。正确做法是批量查：

```java
// 批量查所有学生的课程
Set<Long> studentIds = convertSet(list, StudentDO::getId);
Map<Long, List<StudentCourseDO>> courseMap =
    convertMultiMap(studentCourseMapper.selectListByStudentIds(studentIds),
                    StudentCourseDO::getStudentId);
```

## 五、踩坑清单

| # | 坑 | 症状 | 解法 |
|---|---|---|---|
| 1 | **主表模版没改成【主表】** | 生成的还是单表，没有子表 | 主表选【主表（标准模式）】 |
| 2 | **子表模版没改成【子表】** | 子表被当成独立单表 | 子表选【子表】 |
| 3 | **子表业务名和主表不一致** | 类名不统一，代码散落 | 子表业务名设成和主表一样 |
| 4 | **漏配关联字段** | 生成的代码里没写外键 | 指定【子表关联的字段】= `student_id` |
| 5 | **关联关系选错** | 一对一的生成成了 List | 仔细选"一对多"还是"一对一" |
| 6 | **Service 没加 @Transactional** | 主表存了子表失败，脏数据 | 加事务 |
| 7 | **列表查询 N+1** | 列表接口很慢 | 批量查 + convertMultiMap |
| 8 | **忘了先删后插** | 修改子表后出现重复行 | update 时先 deleteByStudentId |
| 9 | **Vue2 项目用了主子表** | 前端渲染不出来 | 目前只有 Vue3 支持 |
| 10 | 只生成了子表没生成主表 | — | **只对主表点【生成】**，子表会一起出来 |

## 六、一句话总结

**主子表 = 主表 + 外键关联的子表。生成器配置的核心三步：主表【生成模版】选【主表（标准/内嵌/ERP 模式）】、每张子表选【子表】、子表配好"关联主表 + 关联字段 + 关联关系（一对一/一对多）"并把业务名改得和主表一致。代码上记住三点：Service 加事务、子表更新"先删后插"、列表查询批量组装避免 N+1。**

```
你的子表有多少行？
   │
   ├─ 几行（<20）
   │     │
   │     ├─ 想在主列表里就看到明细？

```
