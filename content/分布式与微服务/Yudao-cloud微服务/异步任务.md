# 异步任务（Yudao @Async + 上下文传递）

> **一句话概括**：主流程不该被"记日志""发短信"这种慢活拖住 —— 用 `@Async` 扔到线程池里后台跑。芋道的关键增强是用 **TransmittableThreadLocal（TTL）** 解决了"异步后 ThreadLocal 上下文丢失"这个老大难问题。

---

## 零、先建立整体印象：餐厅点完菜不用站着等

> 🧒 **费曼第 1 段 · 5 岁小孩也能懂**

你去餐厅吃饭，点完菜之后：

- ❌ **同步**：服务员站在你桌边，一直等到你吃完、结完账，才去服务下一桌 —— 蠢爆了
- ✅ **异步**：服务员记下菜单交给后厨，立刻去服务下一桌

程序里也一样。**用户请求"创建订单"**，主流程是：校验 → 扣库存 → 生成订单 → 返回结果。

而"**记录操作日志**""**记录访问日志**""**发通知短信**"这些活，用户根本不关心结果，**没必要让用户等着**。

```
❌ 同步（慢）：
校验(10ms) → 扣库存(50ms) → 生成订单(80ms) → 记日志(30ms) → 发短信(200ms)
                                                          总计 370ms

✅ 异步（快）：
校验(10ms) → 扣库存(50ms) → 生成订单(80ms) → 返回用户 140ms
                                    └─→ 后台线程池：记日志 + 发短信（用户不用等）
```

**芋道用异步的两个真实场景**：操作日志、访问日志。都是"记录一下就行，失败也不影响主流程"的典型。

## 一、原理篇

### 1.1 Spring `@Async` 的基本原理

> 🎓 **费曼第 2 段 · 给高中生讲**

`@Async` 是 Spring 提供的**声明式异步**能力：加个注解，Spring 就用 AOP 把这个方法**提交到线程池**执行，调用方立即返回。

```java
@Async                                   // 👈 加这个注解
public void createApiAccessLogAsync(...) {
    // 这里的代码会在另一个线程里跑
}
```

### 1.2 芋道的关键增强：TransmittableThreadLocal ⭐

**这是本篇最有价值的部分。**

**问题**：你的系统用 `ThreadLocal` 存了当前登录用户信息（芋道的 `SecurityFrameworkUtils` 就是这么干的）。

```java
// 主线程：用户 1001 登录
SecurityContextHolder.setUserId(1001);

// 异步方法里读取
@Async
public void asyncLog() {
    Long userId = SecurityContextHolder.getUserId();   // ❌ 拿到 null！
}
```

**为什么是 null？** 因为 `ThreadLocal` 是**线程隔离**的 —— 主线程存的值，线程池里的另一个线程**根本看不到**。

**芋道的解法**：在 `YudaoAsyncAutoConfiguration` 里配置使用 **TransmittableThreadLocal（TTL，阿里开源）**：

```java
// TransmittableThreadLocal 的核心能力：
// 在提交任务到线程池时，自动把父线程的 ThreadLocal 值"传递"给子线程
TransmittableThreadLocal<String> context = new TransmittableThreadLocal<>();
context.set("user-1001");

executor.submit(() -> {
    System.out.println(context.get());   // ✅ 能拿到 "user-1001"
});
```

> 💡 **官方建议**（值得记住）：
> > "项目使用到 ThreadLocal 的地方，**建议都使用 TransmittableThreadLocal 进行替换**。"
>
> 普通 `ThreadLocal` 在异步/线程池场景下会丢数据，TTL 是生产环境的正确选择。
> 另外还有一个经典场景是 **ThreadLocal 内存泄漏**（线程池复用导致），详见 [[03_JUC 详细讲解]]。

## 二、应用篇

### 2.1 引入依赖

```xml
<dependency>
    <groupId>cn.iocoder.boot</groupId>
    <artifactId>yudao-spring-boot-starter-job</artifactId>
</dependency>
```

> 💡 这个 starter 除了异步任务，还提供**定时任务**能力（Quartz / XXL-Job）。

### 2.2 加 `@Async` 注解

以"异步记录访问日志"为例（`ApiAccessLogServiceImpl`）：

```java
@Service
public class ApiAccessLogServiceImpl implements ApiAccessLogService {

    @Override
    @Async                                     // 👈 声明异步执行
    public void createApiAccessLogAsync(ApiAccessLogCreateReqDTO createReqDTO) {
        // 这个方法会在独立的线程池里执行
        createApiAccessLog(createReqDTO);
    }
}
```

调用方无感知：

```java
// 在拦截器/过滤器里直接调用，立即返回，不阻塞主流程
apiAccessLogService.createApiAccessLogAsync(logDTO);
```

### 2.3 验证效果

随便请求一个 API，看日志里的**线程名**：

```
[nio-8080-exec-1] ... 处理用户请求          ← 主线程（Tomcat 线程）
[yudao-async-1]   ... 记录访问日志          ← 异步线程池（不同线程！）
```

线程名不一样，说明确实异步了。

## 三、进阶篇

### 3.1 `@Async` 失效的 4 个经典原因 ⭐

这是面试高频题，也是实际开发最容易踩的坑：

| 原因 | 说明 | 解决 |
|---|---|---|
| **① 同类内部调用** | `this.asyncMethod()` 不走 Spring AOP 代理 | 注入自己 / 移到另一个类 / `AopContext.currentProxy()` |
| **② 方法不是 public** | AOP 只能代理 public 方法 | 改成 `public` |
| **③ 没开 `@EnableAsync`** | Spring Boot 需显式开启 | 启动类加 `@EnableAsync`（芋道 starter 已自动配置） |
| **④ 返回值不对** | 想要结果却用 `void` | 返回 `CompletableFuture<T>` |

```java
// ❌ 失效：同类内部调用
public void methodA() {
    this.methodB();        // 不经过代理，@Async 无效
}
@Async public void methodB() {}

// ✅ 正确：注入自己
@Resource private ApiAccessLogService self;
public void methodA() {
    self.methodB();        // 走代理，异步生效
}
```

### 3.2 线程池必须自定义（重要）

**Spring 默认的 `SimpleAsyncTaskExecutor` 每次请求都新建线程** —— 高并发下会创建成千上万个线程，直接 OOM。

```java
@Configuration
public class AsyncConfig {

    @Bean("taskExecutor")
    public Executor taskExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(10);          // 核心线程数
        executor.setMaxPoolSize(50);           // 最大线程数
        executor.setQueueCapacity(200);        // 队列容量
        executor.setThreadNamePrefix("yudao-async-");  // 线程名前缀（排障必备）
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());  // 拒绝策略
        executor.initialize();
        return executor;
    }
}
```

> ⚠️ **拒绝策略建议用 `CallerRunsPolicy`**：队列满了就让主线程自己跑。这样虽然慢，但**不会丢任务**。用 `AbortPolicy` 会直接抛异常丢弃日志。

### 3.3 异步任务的 4 个坑

| 坑 | 现象 | 解决 |
|---|---|---|
| **异常被吞掉** | 异步方法抛异常，主流程完全不知道 | 配置 `AsyncUncaughtExceptionHandler`；或返回 `CompletableFuture` 并 `exceptionally` |
| **事务不同步** | 异步方法和主方法不在同一事务 | 异步任务自己开新事务；或改用事务提交后事件 |
| **ThreadLocal 丢失** | 见 1.2 | 用 TransmittableThreadLocal（芋道已配置） |
| **应用关闭时任务丢失** | 队列里的任务还没跑完，JVM 就关了 | 配置线程池 `setWaitForTasksToCompleteOnShutdown(true)` |

### 3.4 什么时候不该用异步

| 场景 | 为什么 |
|---|---|
| 需要立刻拿到结果的 | 异步拿不到，要用 `CompletableFuture.get()`（会阻塞） |
| 强一致性的业务 | 异步失败没法回滚主流程 |
| 任务依赖主流程事务的 | 主流程事务还没提交，异步读不到数据 → 用事务提交后事件 |
| 量特别小的后台任务 | 引入复杂度不划算 |

## 四、一句话总结

| 问题 | 答案 |
|---|---|
| 异步解决什么 | 主流程不被"记日志""发短信"这类慢活拖住 |
| 怎么用 | 方法上加 `@Async`，芋道 starter 已配好线程池 |
| 芋道的增强 | **TransmittableThreadLocal**，解决异步时 ThreadLocal 上下文丢失 |
| 最大坑 | **同类内部调用导致 `@Async` 失效**（AOP 代理问题） |
| 必做 | **自定义线程池**，别用 Spring 默认（会 OOM） |
| 建议 | 项目里所有 ThreadLocal 都换成 TransmittableThreadLocal |
