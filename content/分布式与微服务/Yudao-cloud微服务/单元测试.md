# 单元测试

> **一句话概括**：芋道用 **JUnit5 + Mockito** 写单测（已有 500+ 用例），用**内嵌 H2 内存数据库**模拟 MySQL、用 **jedis-mock** 模拟 Redis。你只要继承 4 个基类中的一个，环境就自动搭好了。

**适合谁读**：想给自己的模块补单测、或者跑不起别人单测的人。
**怎么读**：「一」选对基类，「二」照着 `BaseDbUnitTest` 的流程走一遍，「四」的"Mock 谁、不 Mock 谁"是本篇灵魂。

---

## 零、先建立整体印象：为什么要写单测？

> 官方给的三个价值：**提升代码质量、重复测试效率、部署可靠性**。

💡 **说人话**：

| 场景 | 没单测 | 有单测 |
|---|---|---|
| 改了一个 Service | 手动点半天页面验证，还可能漏 | `mvn test` 一分钟跑完 |
| 重构 | 不敢动，怕改坏 | 随便改，跑一遍就知道 |
| 上线前 | 祈祷 | CI 自动跑，挂了不让合 |
| 新人接手 | 看代码猜 | 看单测就知道这方法干啥 |

⚠️ **现实一点**：不是所有代码都要写单测。**业务逻辑（Service）值得写，CRUD 代码用 [[代码生成【单表】]] 自动生成即可。**

## 一、测试组件：4 个基类，选一个继承

技术组件：`yudao-spring-boot-starter-test`

| 基类 | 用途 | 提供什么 |
|---|---|---|
| ⭐ `BaseMockitoUnitTest` | **纯 Mock 单测**，不碰 DB 和 Redis | Mockito 环境 + `RandomUtils` |
| ⭐ `BaseDbUnitTest` | **需要真实数据库** | 内嵌 **H2 内存数据库** + MyBatis |
| `BaseRedisUnitTest` | 需要 Redis | 内嵌 **Redis**（jedis-mock，端口 16379） |
| `BaseSpringBootUnitTest` | 完整 Spring 容器 | 全量启动（慢，慎用） |

### 怎么选？

```
你的测试要查数据库吗？
   │
   ├─ 不需要（比如短信发送、纯计算逻辑）
   │     → BaseMockitoUnitTest（最快）
   │
   └─ 需要（比如 Service 的 CRUD）
         │
         ├─ 还要用 Redis？
         │     → BaseRedisUnitTest
         │
         └─ 只用 DB
               → BaseDbUnitTest（最常用）
```

### ❓ 什么是内嵌 Redis？

> 官方：*"基于 jedis-mock 开源项目，通过 RedisTestConfiguration 配置类，启动一个 Redis 进程。一般情况下，会使用 16379 端口。"*

💡 **好处**：**不用本地装 Redis，不用连测试环境的 Redis**。单测在任何机器上（包括 CI）都能跑，且**每次跑都是干净的**。

### 两个测试工具类

**① `RandomUtils`**（基于 podam）—— **随机生成 Bean 对象**

```java
// 造一个随机填充的 UserDO（id、username、createTime 全有值）
UserDO user = randomPojo(UserDO.class);

// 造一个随机对象，但指定某些字段
UserDO user = randomPojo(UserDO.class, o -> {
    o.setId(1024L);                    // 指定 id
    o.setStatus(CommonStatusEnum.ENABLE.getStatus());
});

// 造一个随机列表
List<UserDO> users = randomPojoList(UserDO.class, 10);
```

💡 **这省了多少事？** 手写测试数据是单测最烦的部分：
```java
// ❌ 手写
UserDO user = new UserDO();
user.setId(1L);
user.setUsername("test");
user.setMobile("13800138000");
user.setStatus(1);
user.setCreateTime(LocalDateTime.now());
// ... 还有 10 个字段

// ✅ RandomUtils
UserDO user = randomPojo(UserDO.class, o -> o.setUsername("test"));
```

**② `AssertUtils`** —— 增强的断言，支持**忽略部分属性**

```java
// 比较两个对象是否相等，但忽略 createTime（因为每次跑不一样）
assertPojoEquals(userVO, expectedVO, "createTime", "updateTime");
```

## 二、实战：BaseDbUnitTest（以字典类型模块为例）

### 2.1 引入依赖

```xml
<!-- yudao-module-system-biz/pom.xml -->
<dependency>
    <groupId>cn.iocoder.boot</groupId>
    <artifactId>yudao-spring-boot-starter-test</artifactId>
    <scope>test</scope>          <!-- ← 注意是 test 作用域 -->
</dependency>
```

### 2.2 新建测试配置文件

在 `test/resources/` 下建 `application-unit-test.yaml`：

```yaml
spring:
  datasource:
    dynamic:
      primary: primary
      datasource:
        primary:
          url: jdbc:h2:mem:testdb;DB_CLOSE_DELAY=-1;MODE=MySQL
          driver-class-name: org.h2.Driver
          username: sa
          password:
    # 关闭 Druid 监控等生产特性
```

### 2.3 添加 H2 建表脚本 ⭐

修改 `test/resources/sql/` 下的**两个文件**：

**① `create_tables.sql`** —— 建表

```sql
CREATE TABLE IF NOT EXISTS "system_dict_type" (
    "id" bigint NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    "name" varchar(100) NOT NULL DEFAULT '',
    "type" varchar(100) NOT NULL DEFAULT '',
    "status" tinyint NOT NULL DEFAULT '0',
    "remark" varchar(500) DEFAULT NULL,
    "creator" varchar(64) DEFAULT '',
    "create_time" timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    "updater" varchar(64) DEFAULT '',
    "update_time" timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    "deleted" bit NOT NULL DEFAULT FALSE,
    PRIMARY KEY ("id")
) COMMENT '字典类型表';
```

**② `clean.sql`** —— 清数据

```sql
DELETE FROM "system_dict_type";
```

> 官方：*"每次单元测试的方法执行完后，会执行 clean.sql 脚本，进行数据的清理，保证每个单元测试的方法的数据隔离性。"*

💡 **为什么这很重要？** 如果测试数据在方法间残留，测试会**互相污染** —— 单独跑通过、一起跑就挂。**这是单测最常见的疑难杂症。**

### ⚠️ H2 和 MySQL 的语法差异

| MySQL | H2 |
|---|---|
| `AUTO_INCREMENT` | `GENERATED BY DEFAULT AS IDENTITY` |
| `datetime` | `timestamp` |
| `bit(1)` / `tinyint` | `bit` / `tinyint` |
| 反引号 `` `id` `` | 双引号 `"id"` |

**懒得手写转换？** 官方说：**用 [基础设施 → 代码生成] 自动生成 H2 建表语句**（见 [[代码生成【单表】]]）。

### 2.4 写测试类

```java
@Import(DictTypeServiceImpl.class)        // ← 导入要测试的【真实】Bean
public class DictTypeServiceTest extends BaseDbUnitTest {

    @Resource                              // ← 自己模块的：真实 Bean
    private DictTypeService dictTypeService;

    @Resource
    private DictTypeMapper dictTypeMapper;

    @MockBean                              // ← 别人模块的：Mock 掉
    private DictDataService dictDataService;

    @Test
    public void testCreateDictType_success() {
        // ① 准备数据：随机造一个 ReqVO
        DictTypeSaveReqVO reqVO = randomPojo(DictTypeSaveReqVO.class,
            o -> o.setStatus(CommonStatusEnum.ENABLE.getStatus()));

        // ② 调用被测方法
        Long dictTypeId = dictTypeService.createDictType(reqVO);

        // ③ 断言结果
        assertNotNull(dictTypeId);
        DictTypeDO dictType = dictTypeMapper.selectById(dictTypeId);
        assertPojoEquals(reqVO, dictType);         // 比较对象，自动忽略有差异的字段
    }
}
```

### ⭐ 灵魂拷问：为什么 `dictTypeMapper` 是真实的，`dictDataService` 要 Mock？

> 官方解释得非常好，我复述一遍：
>
> **"单元测试需要避免对外部的依赖，而 dictDataService 是外部依赖，所以需要 Mock 掉。"**
>
> **"dictTypeMapper 某种程度来说，也是一种外部依赖，但是通过内嵌的 H2 内存数据库，进行'真实'的数据库操作，反而单元测试的编写效率更高，效果更好，所以不需要 Mock 掉。"**

💡 **翻译成决策树**：

```
这个 Bean 是外部依赖吗？
   │
   ├─ 是（别的模块的 Service、第三方 API、MQ、Redis）
   │     → @MockBean 掉
   │     理由：① 别人的逻辑不该由我测试
   │          ② 别人的服务可能不可用（网络、环境）
   │          ③ 我想要精确控制它的返回值，覆盖各种分支
   │
   └─ 是"基础设施"吗？（Mapper / H2 数据库）
         → 用真实的
         理由：Mock Mapper 要写一堆 when(...).thenReturn(...)，
               比直接插数据查数据还麻烦，而且测不出 SQL 错误
```

⚠️ **这个判断很重要**：**Mock Mapper 是单测新手常见的过度设计**。你 Mock 了 Mapper，就测不出 SQL 写错了 —— 那这个单测还有什么价值？

## 三、Mockito 三板斧

所有单测都是这三步：**准备（Given）→ 执行（When）→ 断言（Then）**

```java
@Test
public void testUpdateUser_userNotFound() {
    // ===== ① 准备：定义 Mock 行为 =====
    // 当调用 getUser(999L) 时，返回 null（模拟"用户不存在"）
    when(userMapper.selectById(999L)).thenReturn(null);

    // ===== ② 执行 =====
    // ===== ③ 断言：应该抛异常 =====
    assertServiceException(() -> userService.updateUser(reqVO), USER_NOT_EXISTS);
}
```

**常用 Mockito 方法**：

| 方法 | 作用 |
|---|---|
| `when(xxx).thenReturn(yyy)` | 定义返回值 |
| `when(xxx).thenThrow(new RuntimeException())` | 定义抛异常 |
| `verify(mock).method()` | **验证方法被调用过** |
| `verify(mock, times(2)).method()` | 验证调用了 2 次 |
| `verify(mock, never()).method()` | 验证**从未**调用 |
| `any()` / `anyLong()` / `eq(1L)` | 参数匹配器 |

**示例：验证"删除角色时，真的删了关联表"**

```java
@Test
public void testDeleteRole() {
    // 准备
    RoleDO role = randomPojo(RoleDO.class);
    roleMapper.insert(role);

    // 执行
    roleService.deleteRole(role.getId());

    // 断言：角色真的被删了
    assertNull(roleMapper.selectById(role.getId()));

    // 验证：角色菜单关联也被删了（Mock 的话就 verify）
    verify(roleMenuService).deleteByRoleId(role.getId());
}
```

## 四、实战：BaseMockitoUnitTest（纯 Mock）

**场景**：`SmsSendService` 不依赖 DB 和 Redis（只调用第三方短信 API），所以用纯 Mock 基类，**启动最快**。

```java
@Import(SmsSendServiceImpl.class)
public class SmsSendServiceTest extends BaseMockitoUnitTest {

    @Resource
    private SmsSendService smsSendService;

    @MockBean
    private SmsClientFactory smsClientFactory;      // 第三方客户端：Mock

    @MockBean
    private SmsTemplateService smsTemplateService;  // 模板查询：Mock

    @Test
    public void testSendSms_success() {
        // ① Mock 模板查询
        SmsTemplateDO template = randomPojo(SmsTemplateDO.class,
            o -> o.setStatus(CommonStatusEnum.ENABLE.getStatus()));
        when(smsTemplateService.getSmsTemplate(anyLong())).thenReturn(template);

        // ② Mock 第三方客户端
        SmsClient client = mock(SmsClient.class);
        when(client.getChannel()).thenReturn(SmsChannelEnum.ALIYUN);
        when(smsClientFactory.getSmsClient(any())).thenReturn(client);

        // ③ 执行 + 断言
        Long logId = smsSendService.sendSingleSms(...);
        assertNotNull(logId);
    }
}
```

## 五、单测该覆盖哪些方法？

代码生成器会自动生成这些方法的单测（见 [[代码生成【单表】]]）：

| 方法类型 | 测什么 |
|---|---|
| **新增** | 正常插入；字段缺失时报错；唯一约束冲突时报错 |
| **修改** | 正常更新；id 不存在时报错 |
| **删除** | 正常删除；id 不存在时不报错（幂等） |
| **单条查询** | 查得到；查不到返回 null |
| **分页查询** | 条件过滤正确；总数正确；空结果 |

💡 **至少要覆盖"正常路径 + 一个异常路径"**。只测 happy path 的单测，价值减半。

## 六、踩坑清单

| # | 坑 | 症状 | 解法 |
|---|---|---|---|
| 1 | **忘了加 `clean.sql`** | 单测互相污染，单独跑过、一起跑挂 | 每个表都要写 DELETE 语句 |
| 2 | H2 建表语句用了 MySQL 语法 | 启动时 `Table "xxx" not found` | 用代码生成器自动生成 H2 脚本 |
| 3 | Mock 了 Mapper | 测不出 SQL 错误，单测形同虚设 | Mapper 用真实的 H2 |
| 4 | 该 Mock 的没 Mock | 单测依赖外部环境，CI 上跑挂 | 外部依赖一律 `@MockBean` |
| 5 | `randomPojo` 生成的字段不符合约束 | 插入报唯一键冲突 | 用 lambda 指定关键字段 |
| 6 | 继承了 `BaseSpringBootUnitTest` | 单测跑几十秒 | 换更轻的基类 |
| 7 | 断言比较了 `createTime` | 时间对不上，测试失败 | 用 `assertPojoEquals(..., "createTime")` 忽略 |
| 8 | 测试类没加 `@Import` | `@Resource` 注入是 null | 导入要测的实现类 |
| 9 | 忘了 `<scope>test</scope>` | 测试依赖被打进生产包 | 加上作用域 |
| 10 | 事务没回滚 | 数据残留 | `BaseDbUnitTest` 里有事务回滚，配合 `clean.sql` 双保险 |

### 💡 坑 5 展开：randomPojo 的字段约束

`randomPojo` 是**完全随机**的，可能生成不符合业务约束的值：

```java
// ❌ 可能生成 status = 999（枚举里没有）
DictTypeDO dictType = randomPojo(DictTypeDO.class);

// ✅ 指定关键字段
DictTypeDO dictType = randomPojo(DictTypeDO.class, o -> {
    o.setStatus(CommonStatusEnum.ENABLE.getStatus());   // 用枚举值
    o.setType("test_type_" + RandomUtil.randomString(5));  // 保证唯一
});
```

## 七、一句话总结

**单测用 JUnit5 + Mockito，继承 4 个基类之一：`BaseMockitoUnitTest`（纯 Mock，最快）、`BaseDbUnitTest`（内嵌 H2，最常用）、`BaseRedisUnitTest`（内嵌 Redis）。关键原则：自己模块的用真实 Bean（含 Mapper），别人模块的用 `@MockBean`；每个表都要在 `create_tables.sql` 建表 + `clean.sql` 清数据，保证测试隔离。`randomPojo()` 造数据，`assertPojoEquals()` 断言并忽略时间字段。**

## 附录：一个完整的单测模板

```java
@Import(XxxServiceImpl.class)              // ① 导入实现类
public class XxxServiceTest extends BaseDbUnitTest {   // ② 选对基类

    @Resource
    private XxxService xxxService;         // ③ 自己的：真实 Bean
    @Resource
    private XxxMapper xxxMapper;

    @MockBean
    private OtherService otherService;     // ④ 别人的：Mock 掉

    @Test
    public void testCreateXxx_success() {
        // Given：准备数据
        XxxSaveReqVO reqVO = randomPojo(XxxSaveReqVO.class, o -> {
            o.setStatus(CommonStatusEnum.ENABLE.getStatus());
        });

        // When：执行
        Long id = xxxService.createXxx(reqVO);

        // Then：断言
        assertNotNull(id);
        XxxDO actual = xxxMapper.selectById(id);
        assertPojoEquals(reqVO, actual, "createTime");
    }

    @Test
    public void testCreateXxx_duplicateName() {
        // Given：先插一条同名的
        XxxDO exist = randomPojo(XxxDO.class, o -> o.setName("芋道"));
        xxxMapper.insert(exist);

        // When & Then：应该抛异常
        XxxSaveReqVO reqVO = randomPojo(XxxSaveReqVO.class, o -> o.setName("芋道"));
        assertServiceException(() -> xxxService.createXxx(reqVO), XXX_NAME_DUPLICATE);
    }
}
```
