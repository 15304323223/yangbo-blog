# 参数校验、时间传参

> **一句话概括**：用 **Hibernate Validator** 的注解（`@NotNull`/`@NotEmpty`/`@Mobile`）在方法入口就把脏参数挡回去，校验失败自动返回 `400 请求参数不正确:xxx`；**时间统一用 `LocalDateTime`，Query 传 `yyyy-MM-dd HH:mm:ss` 字符串，JSON 传 Long 时间戳**。

**适合谁读**：所有写接口的人。这两块是"每天都要写、但总有人写错"的基础。
**怎么读**：「一」抄注解表，「二」记住三步开启法，「三」的时间坑必看。

---

## 零、先建立整体印象：门口的安检

想象银行门口的安检：

```
没有校验（❌）：谁都能进，进来才发现他带刀 → 业务代码里到处 if 判断
有了校验（✅）：门口拦住，直接告诉他"你不能带刀进来" → 一行注解搞定
```

**参数校验的位置**：

```
前端请求
   │
   ▼ ① Controller 层校验（第一道门）
   │    @Valid + @NotNull → 挡掉格式错误
   │
   ▼ ② Service 层校验（第二道门）⚠️ 必做！
   │    因为 Service 可能被别的 Service 调用
   │
   ▼ ③ 数据库约束（最后一道）
       唯一索引、非空约束
```

**校验失败的响应**（全局异常处理器自动转换，见 [[异常处理（错误码）]]）：

```json
{
  "code": 400,
  "data": null,
  "msg": "请求参数不正确:密码不能为空"
}
```

## 一、参数校验注解速查表

Hibernate Validator 内置 20+ 个注解，芋道把它们分成常用和不常用两类。

### 1.1 常用注解（背下来就够用）

| 注解 | 功能 | 用在 | 例子 |
|---|---|---|---|
| `@NotNull` | **不能为 null** | 任意类型 | `@NotNull(message = "编号不能为空") Long id` |
| `@NotEmpty` | **不能为 null 且不能为空串/空集合** | String、Collection、Map、Array | `@NotEmpty(message = "密码不能为空")` |
| `@NotBlank` | **不能为 null 且 trim 后不为空串** | 只能 String | `@NotBlank(message = "名称不能为空")` |
| `@Pattern(value)` | 必须匹配正则 | String | `@Pattern(regexp = "^[A-Za-z0-9]+$")` |
| `@Size(max, min)` | 长度/大小在范围内 | String、Collection、Map、Array | `@Size(min = 1, max = 10)` |
| `@Length(max, min)` | 字符串长度范围 | String | `@Length(min = 4, max = 16)` |
| `@Max(value)` | 最大值 | 数字、String | `@Max(value = 100)` |
| `@Min(value)` | 最小值 | 数字、String | `@Min(value = 1)` |
| `@Range(min=, max=)` | 值在范围内 | 数字、String | `@Range(min = 0, max = 1)` |
| `@Email` | 必须是邮箱格式 | String | |
| `@AssertTrue` / `@AssertFalse` | 必须为 true / false | Boolean | 比如"必须同意协议" |

### 1.2 `@NotNull` / `@NotEmpty` / `@NotBlank` 的区别 ⭐

**这是最高频的混淆点**，一张表说清：

| 值 | `@NotNull` | `@NotEmpty` | `@NotBlank` |
|---|---|---|---|
| `null` | ❌ 失败 | ❌ 失败 | ❌ 失败 |
| `""`（空串） | ✅ 通过 | ❌ 失败 | ❌ 失败 |
| `" "`（空格） | ✅ 通过 | ✅ 通过 | ❌ 失败 |
| `"abc"` | ✅ 通过 | ✅ 通过 | ✅ 通过 |
| `[]`（空集合） | ✅ 通过 | ❌ 失败 | 不支持 |

💡 **记忆口诀**：
- **`@NotNull`** —— 只管"是不是 null"
- **`@NotEmpty`** —— 管"是不是 null 或空的"（空串、空集合都算空）
- **`@NotBlank`** —— 最严格，"只有空格也算空"（**只能用在 String**）

⚠️ **注意**：`@NotBlank` 用在 `Long`、`List` 上会**启动报错**（类型不匹配）。

### 1.3 不常用注解

| 注解 | 功能 |
|---|---|
| `@Null` | 必须为 null（很少用） |
| `@DecimalMax(value)` / `@DecimalMin(value)` |  BigDecimal 的最大值/最小值 |
| `@Digits(integer, fraction)` | 限制整数位和小数位数（金额场景） |
| `@Positive` / `@PositiveOrZero` | 必须为正数 / 正数或 0 |
| `@Negative` / `@NegativeOrZero` | 必须为负数 / 负数或 0 |
| `@Past` / `@PastOrPresent` | 必须是过去时间 / 过去或现在 |
| `@Future` / `@FutureOrPresent` | 必须是未来时间 / 未来或现在 |

💡 **`@Future` 很实用**：预约时间、活动结束时间必须晚于现在。

## 二、怎么开启参数校验（三步）

### 第 0 步：确认依赖（一般不用做）

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

芋道已经引好了。

### 第 1 步：在类上加 `@Validated`

```java
// Controller 示例
@Validated
public class AuthController {}

// Service 示例 —— 一般放在【实现类】上
@Service
@Validated
public class AdminAuthServiceImpl implements AdminAuthService {}
```

⚠️ **为什么 Service 要加在实现类和接口上不同位置？** 因为 `@Validated` 是 Spring 的 AOP 注解，加在实现类上才能被 Spring 代理到。

### 第 2 步（情况一）：参数是 Bean 类型 → 加 `@Valid`

```java
@Validated
public class AuthController {

    @PostMapping("/login")
    public CommonResult<AuthLoginRespVO> login(@RequestBody @Valid AuthLoginReqVO reqVO) {}
    //                                                     ↑ 关键：@Valid
}

// Service 接口上也要加
public interface AdminAuthService {
    String login(@Valid AuthLoginReqVO reqVO, String userIp, String userAgent);
}
```

**Bean 类里写校验规则**：

```java
@Data
public class AuthLoginReqVO {

    @NotEmpty(message = "登录账号不能为空")
    @Length(min = 4, max = 16, message = "账号长度为 4-16 位")
    @Pattern(regexp = "^[A-Za-z0-9]+$", message = "账号格式为数字以及字母")
    private String username;

    @NotEmpty(message = "密码不能为空")
    @Length(min = 4, max = 16, message = "密码长度为 4-16 位")
    private String password;
}
```

💡 **官方建议**：*"一般建议添加参数注解到属性上。原因：采用 Lombok 后，很少使用 getter 方法。"*

（注解也可以加在 getter 上，但用了 `@Data` 就不写 getter 了，所以加字段上。）

### 第 2 步（情况二）：参数是普通类型 → 直接加注解

```java
@Validated
public class DictDataController {

    @GetMapping("/get")
    public CommonResult<DictDataRespVO> getDictData(
            @RequestParam("id") @NotNull(message = "编号不能为空") Long id) {}
    //                            ↑ 直接加在参数上
}

// Service 同理
public interface DictDataService {
    DictDataDO getDictData(@NotNull(message = "编号不能为空") Long id);
}
```

### 第 3 步：启动项目，少填几个参数测试

### ❓ Controller 校验了，Service 还要校验吗？

> 官方：**"是需要的。Service 可能会被别的 Service 进行调用，也会存在参数不正确的情况，所以必须进行参数校验。"**

💡 **画个图**：

```
HTTP 请求 ──> Controller(@Valid 校验) ──> Service
                                            ▲
定时任务 ────────────────────────────────────┘  ← 这条路绕过了 Controller！
MQ 消费者 ──────────────────────────────────┘  ← 这条也绕过了
别的 Service ───────────────────────────────┘  ← 这条也
```

**Controller 只是入口之一。** Service 才是业务的核心防线。

## 三、自定义校验注解：以 @Mobile 为例

内置注解不够用？自己造。芋道在 `yudao-common` 的 `validation` 包下造了好几个，比如 `@Mobile`。

### 第 1 步：定义注解

```java
@Target({
    ElementType.METHOD,
    ElementType.FIELD,              // 用在字段上
    ElementType.ANNOTATION_TYPE,
    ElementType.CONSTRUCTOR,
    ElementType.PARAMETER,          // 用在方法参数上
    ElementType.TYPE_USE
})
@Retention(RetentionPolicy.RUNTIME)
@Documented
@Constraint(
    validatedBy = MobileValidator.class     // ← 指定校验器
)
public @interface Mobile {

    String message() default "手机号格式不正确";   // 默认错误提示

    Class<?>[] groups() default {};              // 分组校验用

    Class<? extends Payload>[] payload() default {};
}
```

### 第 2 步：写校验器

```java
public class MobileValidator implements ConstraintValidator<Mobile, String> {

    @Override
    public void initialize(Mobile annotation) {
        // 初始化，一般留空
    }

    @Override
    public boolean isValid(String value, ConstraintValidatorContext context) {
        // ⚠️ 关键：空值直接放行，交给 @NotEmpty 管
        if (StrUtil.isEmpty(value)) {
            return true;
        }
        // 真正的校验逻辑
        return ValidationUtils.isMobile(value);
    }
}
```

💡 **为什么空值要返回 true？**

这是**约定俗成的设计**：一个注解只管一件事。`@Mobile` 只管"格式对不对"，"填没填"归 `@NotEmpty` 管。

**如果这里返回 false 会怎样？** 用户不填手机号 → 同时报"手机号不能为空"和"手机号格式不正确"两条 → **体验很差**。

### 第 3 步：使用

```java
public class AppAuthLoginReqVO {

    @NotEmpty(message = "手机号不能为空")     // 管填没填
    @Mobile                                  // 管格式对不对
    private String mobile;
}
```

## 四、时间传参：三种场景三种格式 ⭐

**这是最容易出 bug 的地方**，因为**不同场景的格式要求不一样**。

### 4.1 Query 传参（GET 请求 / form-data）→ 字符串

**后端**要加 `@DateTimeFormat`：

```java
// JobLogPageReqVO.java
@DateTimeFormat(pattern = FORMAT_YEAR_MONTH_DAY_HOUR_MINUTE_SECOND)  // yyyy-MM-dd HH:mm:ss
private LocalDateTime beginTime;

// UserPageReqVO.java —— 日期范围用数组
@DateTimeFormat(pattern = FORMAT_YEAR_MONTH_DAY_HOUR_MINUTE_SECOND)
private LocalDateTime[] createTime;
```

**前端**传：`yyyy-MM-dd HH:mm:ss`

```
GET /admin-api/system/user/page?createTime[]=2026-09-01 00:00:00&createTime[]=2026-09-30 23:59:59
```

参考：
- `views/infra/job/logger/index.vue` 的 `beginTime` / `endTime`
- `views/system/user/index.vue` 的 `createTime`

⚠️ **不加 `@DateTimeFormat` 会怎样？** Spring 默认按 ISO 格式（`2026-09-01T00:00:00`）解析，传 `2026-09-01 00:00:00` 会报 `400 参数类型不匹配`。

### 4.2 Request Body（JSON）→ Long 时间戳

**后端**：用 `@RequestBody` + `LocalDateTime` 属性，**什么都不用加**。

```java
@PostMapping("/create")
public CommonResult<Long> createTenant(@RequestBody @Valid TenantSaveReqVO reqVO) {}

@Data
public class TenantSaveReqVO {
    private LocalDateTime expireTime;    // ← 接收 Long 时间戳
}
```

**前端**传：`Long 时间戳`（毫秒）

```json
{ "expireTime": 1785000000000 }
```

⚠️ **注意**：Query 用字符串、Body 用时间戳 —— **同一个字段，两种格式**。这是芋道的约定，不要混。

### 4.3 Response Body（返回）→ Long 时间戳

**返回的 JSON 里，时间也是 Long 时间戳**。

```json
{
  "code": 0,
  "data": {
    "id": 102,
    "createTime": 1757000000000     ← 时间戳，不是字符串
  }
}
```

### 4.4 ❓ 为什么用 Long 时间戳？

> 官方原话（说得很好）：
> *"每个项目希望展示的时间格式可能不同，有希望 yyyy-MM-dd HH:mm:ss，也有希望 yyyy/MM/dd HH:mm:ss，又或者是其它。而 Long 时间戳是比较标准的，没有任何'产品需求'的味道，所以使用它。至于业务希望展示成什么样子，可以通过前端封装统一的 format 方法去实现，更加规范。"*

💡 **翻译成人话**：

| 方案 | 问题 |
|---|---|
| 后端返回 `2026-09-01 10:00:00` | A 页面要显示"3分钟前"，B 页面要"09-01"，C 页面要"2026年9月1日" → **每种格式都得后端转一次** |
| 后端返回 `1757000000000` | 后端不管展示，**前端拿时间戳随便格式化** ✅ |

**额外的好处**：
1. **没有时区问题** —— 时间戳是绝对的 UTC 毫秒数，客户端按自己时区显示
2. **没有格式歧义** —— `2026-01-02` 是 1月2日还是 2月1日？时间戳没这问题
3. **省流量** —— 13 位数字比 19 位字符串短

实现：自定义了 `TimestampLocalDateTimeSerializer` 和 `TimestampLocalDateTimeDeserializer`。

### 4.5 我想改格式怎么办？

#### 方案 A：全局改成 `yyyy-MM-dd HH:mm:ss`

用 Jackson 内置的序列化器替换掉芋道的：

```java
@Bean
public Jackson2ObjectMapperBuilderCustomizer jacksonCustomizer() {
    return builder -> {
        // 序列化：LocalDateTime → "yyyy-MM-dd HH:mm:ss"
        builder.serializerByType(LocalDateTime.class,
            new LocalDateTimeSerializer(DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss")));
        // 反序列化：字符串 → LocalDateTime
        builder.deserializerByType(LocalDateTime.class,
            new LocalDateTimeDeserializer(DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss")));
    };
}
```

#### 方案 B：只改某几个字段（推荐 ✅）

用 `@JsonFormat`：

```java
// UserRespVO.java
@JsonSerialize(using = LocalDateTimeSerializer.class)
@JsonDeserialize(using = LocalDateTimeDeserializer.class)
@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")
private LocalDateTime createTime;
```

💡 **实际项目里最常用的就是方案 B** —— 全局保持时间戳，个别字段特殊处理（比如"生日"只要年月日）。

## 五、踩坑清单

| # | 坑 | 症状 | 解法 |
|---|---|---|---|
| 1 | **Bean 参数忘了加 `@Valid`** | 校验完全不生效 | `@RequestBody @Valid XxxReqVO` |
| 2 | 类上忘了加 `@Validated` | Service 层校验不生效 | 加 `@Validated` |
| 3 | Query 时间没加 `@DateTimeFormat` | 400 参数类型错误 | 加上并指定 pattern |
| 4 | JSON 里传了时间字符串 | 反序列化失败 | 传 Long 时间戳 |
| 5 | `@NotBlank` 用在 Long 上 | 启动报错 | 换 `@NotNull` |
| 6 | 自定义校验器对 null 返回 false | 同时报两条错误 | null 时返回 true |
| 7 | Service 层没校验 | 定时任务/MQ 调用时脏数据入库 | Service 也要加 |
| 8 | 校验异常被 catch 成 500 | 前端收到"系统异常" | 让 `MethodArgumentNotValidException` 冒到全局处理器 |
| 9 | 时间戳传成秒（10 位） | 时间变成 1970 年 | 必须是**毫秒**（13 位） |

### 坑 9 展开：10 位 vs 13 位

```javascript
// JavaScript 里
Date.now()              // 1757000000000  ← 13 位毫秒 ✅
Math.floor(Date.now()/1000)  // 1757000000  ← 10 位秒 ❌
```

Java 的 `Instant.ofEpochMilli()` 需要**毫秒**。传秒会解析成 **1970-01-20**（因为 1757000000 毫秒 ≈ 20 天）。

💡 **排查技巧**：如果看到时间全是 1970 年，99% 是秒/毫秒搞混了。

---

## 六、一句话总结

**参数校验三步：类上加 `@Validated`、Bean 参数加 `@Valid`、字段上加 `@NotNull`/`@NotEmpty` 等注解；Service 层也要校验（因为 MQ、定时任务会绕过 Controller）。时间传参记住：Query 用 `@DateTimeFormat` + `yyyy-MM-dd HH:mm:ss` 字符串，JSON 用 Long 毫秒时间戳，返回也是时间戳（前端自己格式化）。**
