# 文件存储（上传下载）

> **一句话概括**：芋道把文件上传抽象成一个 `FileClient` 接口，下面挂了 5 种实现（S3 对象存储 / 本地磁盘 / FTP / SFTP / 数据库），**你只管调 `fileService.createFile()`，具体存哪由配置决定**。最推荐的是**兼容 S3 协议的对象存储**，其次是数据库，最不推荐本地磁盘。

**适合谁读**：要做头像上传、附件上传、Excel 导出下载的人。
**怎么读**：「零」先决定用哪种存储，「一」学两种上传姿势，「二」的**前端直传**是本篇最有价值的部分。

---

## 零、先建立整体印象：三种存文件的地方

想象你要存放一批货：

| 存储方案 | 类比 | 支持的具体服务 | 芋道推荐度 |
|---|---|---|---|
| **① S3 协议对象存储** | 租一个**专业仓库**（有专人管理、随时可取、按量付费） | MinIO、七牛云 Kodo、腾讯云 COS、阿里云 OSS、华为云 OBS、亚马逊 S3 | ✅✅ **首选** |
| **② 磁盘存储** | 堆在**自家客厅** | 本地磁盘、FTP 服务器、SFTP 服务器 | ❌ **不推荐** |
| **③ 数据库存储** | 存进**银行保险柜** | MySQL、Oracle、PostgreSQL、SQL Server | ✅ 次选 |

### 为什么这么排？

**① 为什么首选 S3 对象存储？**
- 天然支持 HTTP 访问，上传完直接拿到一个 URL，前端 `<img src="...">` 就能显示
- 便宜、无限扩容、自带 CDN 加速
- 几乎所有云厂商都兼容 S3 协议 → **换云厂商不用改代码**

> 官方建议：*"如果无法使用云服务，可以自己搭建一个 MinIO 服务。"* MinIO 是开源的对象存储，装在你自己服务器上，接口和 S3 一模一样。

**③ 为什么数据库排第二？**
>*"数据库的主从机制可以实现高可用，备份也方便，少量小文件问题不大。"*

适合：内网系统、文件很少很小、不想单独运维一个对象存储。

**② 为什么不推荐磁盘？**
>*"主要是实现高可用比较困难，无法实现故障转移。"*

💥 **致命问题**：文件存在本机磁盘上，
- 你部署 3 台服务器做负载均衡 → 用户上传到 A 机器，下次请求打到 B 机器 → **文件不见了**
- 服务器硬盘坏了 → 文件全丢
- 想解决？得上 NFS 共享存储或 rsync 同步 —— 又是运维噩梦

## 一、原理篇：FileClient 抽象

### 1.1 一个接口，5 种实现

在 `yudao-module-infra-biz` 模块的 `framework/file` 包下，定义了核心接口：

```java
public interface FileClient {

    /**
     * 获得客户端编号（对应 infra_file_config 表的主键）
     */
    Long getId();

    /**
     * 上传文件
     * @param content 文件内容（字节数组）
     * @param path    相对路径
     * @return 完整路径，即 HTTP 访问地址
     */
    String upload(byte[] content, String path);

    /**
     * 删除文件
     */
    void delete(String path);

    /**
     * 获得文件的内容
     */
    byte[] getContent(String path);

}
```

**5 个实现类**（UML 类图见官方截图）：

```
                FileClient (接口)
                      │
    ┌─────────┬───────┼───────┬──────────┐
    │         │       │       │          │
S3FileClient  │  FtpFileClient │   DBFileClient
         LocalFileClient  SftpFileClient
```

| 实现类 | 存储位置 | 备注 |
|---|---|---|
| `S3FileClient` | S3 兼容对象存储 | **推荐** |
| `LocalFileClient` | 本地磁盘 | 开发调试用 |
| `FtpFileClient` | FTP 服务器 | 老系统对接 |
| `SftpFileClient` | SFTP 服务器 | 更安全的文件服务器 |
| `DBFileClient` | 数据库 `infra_file_content` 表 | 小文件场景 |

💡 **这就是典型的策略模式**。业务代码只依赖 `FileClient` 接口，换存储只需改配置，不用改一行 Java 代码。

### 1.2 上传的完整调用链

```
Controller: /admin-api/infra/file/upload
   │
   ▼
FileService.createFile(name, path, content)
   │
   ├─ ① 拿到【主配置】的 FileClient（从 infra_file_config 表读，默认那条）
   ├─ ② 生成文件名（UUID，防重名、防覆盖）
   ├─ ③ client.upload(content, path)   → 真正存到 S3 / 磁盘 / 数据库
   ├─ ④ 把文件信息 INSERT 到 infra_file 表（记录文件名、URL、大小、类型）
   └─ ⑤ 返回完整访问 URL
```

⚠️ **关键点：文件记录落库了**（`infra_file` 表）。所以你能看到"文件列表"、能删除、能追溯谁传的。

### 1.3 文件内容 vs 文件记录，两张表

| 表 | 存什么 |
|---|---|
| `infra_file` | 文件**元数据**：文件名、URL、大小、类型、上传时间（**所有存储方案都写**） |
| `infra_file_content` | 文件**二进制内容**（**只有 DBFileClient 才用**） |

## 二、应用篇：怎么用

### 2.1 配置一个存储器（以七牛云为例）

**①** 打开 [基础设施 → 文件管理 → 文件配置] → [新增]
**②** 存储器选 **【S3 对象存储器】**，填写：

```
节点地址：    s3.cn-south-1.qiniucs.com
存储 bucket： ruoyi-vue-pro
accessKey：   ***
accessSecret：***
自定义域名：  http://test.yudao.iocoder.cn
```

⚠️ **注意**：官方文档里给的七牛云 key 是作者**公开给大家体验的测试账号**，**请勿在测试或生产环境使用**（而且随时可能失效）。

**③** 点击该行的 **[测试]** 按钮，验证配置是否正确
**④** 测试通过后，点击 **[主配置]** 按钮，设为默认 —— 后续上传都用它

### 2.2 方式一：前端上传（最常见）

后端提供的接口：

```java
// FileController.java
@PostMapping("/upload")
@Operation(summary = "上传文件")
public CommonResult<String> uploadFile(FileUploadReqVO uploadReqVO) throws Exception {
    MultipartFile file = uploadReqVO.getFile();
    String path = uploadReqVO.getPath();
    //                                                    ↓ 读取文件字节
    return success(fileService.createFile(file.getOriginalFilename(), path,
            IoUtil.readBytes(file.getInputStream())));
}
```

**调用路径**：`POST /admin-api/infra/file/upload`，表单带 `file` 和 `path`。

前端组件参考：
- 文件列表上传：`src/views/infra/file/index.vue`
- 头像修改：`src/views/system/user/userAvatar.vue`

### 2.3 方式二：后端上传（Java 代码里传）

比如"用户注册时自动生成默认头像"、"定时生成报表上传"。

```java
// 引入 FileApi
@Resource
private FileApi fileApi;

public void someMethod() {
    byte[] content = generateReportBytes();          // 生成文件内容
    String url = fileApi.createFile("report/2026-09.xlsx", content);
    //     ↑ 返回：http://test.yudao.iocoder.cn/xxx.xlsx
}
```

**接口定义**：

```java
/**
 * 保存文件，并返回文件的访问路径
 *
 * @param path    文件路径
 * @param content 文件内容
 * @return 文件路径
 */
String createFile(String path, byte[] content);
```

⚠️ **前提**：你的 Maven 模块要引入依赖：

```xml
<dependency>
    <groupId>cn.iocoder.boot</groupId>
    <artifactId>yudao-module-infra-api</artifactId>
    <version>${revision}</version>
</dependency>
```

（比如 `yudao-module-system-biz` 要传头像，就得引这个。）

### 2.4 文件下载

上传成功后返回的是**完整 URL 访问路径**，例如：
`http://test.yudao.iocoder.cn/822aebded6e6414e912534c6091771a4.jpg`

**不同存储器的 URL 规则不同**：

| 存储器 | URL 能直接访问吗 | 做法 |
|---|---|---|
| **S3 对象存储** | ✅ 能 | 直接用 S3 返回的 URL |
| **数据库 / 本地磁盘** | ❌ 不能 | 必须走后端接口：`/admin-api/infra/file/{configId}/get/{path}` |

后端的下载接口：

```java
// FileController.java
@GetMapping("/{configId}/get/**")
@PermitAll                                    // ← 无需登录就能访问（图片可以直接 <img src>）
@Operation(summary = "下载文件")
public void getFileContent(HttpServletRequest request,
                           HttpServletResponse response,
                           @PathVariable("configId") Long configId) throws Exception {
    // ① 从 URL 里截出文件路径
    String path = StrUtil.subAfter(request.getRequestURI(), "/get/", false);
    if (StrUtil.isEmpty(path)) {
        throw new IllegalArgumentException("结尾的 path 路径必须传递");
    }

    // ② 读取文件内容
    byte[] content = fileService.getFileContent(configId, path);
    if (content == null) {
        log.warn("[getFileContent][configId({}) path({}) 文件不存在]", configId, path);
        response.setStatus(HttpStatus.NOT_FOUND.value());
        return;
    }

    // ③ 写给前端
    ServletUtils.writeAttachment(response, path, content);
}
```

⚠️ **安全提醒**：这个接口是 `@PermitAll`（免登录）的。意味着**只要知道 URL 就能下载文件**。如果存的是敏感文件（合同、身份证照片），**别用数据库/磁盘存储**，或者自己加权限校验。

## 三、进阶篇：前端直传 S3【本篇最有价值】

### 3.1 为什么要前端直传？

**传统方式（经过后端）**：

```
用户浏览器 ──[10MB 文件]──> 后端服务器 ──[10MB 文件]──> S3 存储器
             上传 10s               上传（内网，很快）
```

问题：**文件流量要经过后端服务器**。

> 官方举的例子：*"上传文件有 10MB，后端服务器带宽只有 1MB，那么上传文件就需要 10 秒。如果多个人上传文件，就会导致后端服务器的带宽被占满。"*

💥 **后果**：几个人同时上传视频，你的业务接口全卡死（带宽被文件占满了）。

**前端直传方式**：

```
用户浏览器 ────────────[10MB 文件，走用户自己的 100M 宽带]──────────> S3 存储器
    │
    └─[先向后端要一个临时上传凭证]──> 后端（只返回几十字节的签名，不传文件）
```

> 官方：*"上传文件有 10MB，用户的带宽有 100MB，那么上传文件就需要 0.1 秒。"*

**速度提升 100 倍，后端带宽占用降到 0。**

### 3.2 怎么开启（4 步）

**① 新增 S3 配置**

和前面「2.1」一样，在 [文件配置] 里加一个 S3 存储器，设为**主配置**。

**② 配置 S3 的跨域（CORS）**

⚠️ **这步不做，前端直传一定失败**（浏览器同源策略拦截）。

- 七牛云：控制台 → 空间设置 → 跨域资源共享
- 阿里云 OSS：控制台 → 权限管理 → 跨域访问
- 腾讯云 COS：控制台 → 安全管理 → 跨域访问

一般配置：来源 Origins 填你的前端域名（或开发时填 `*`），允许 Methods 勾 `PUT`/`POST`/`GET`。

**③ 修改前端配置**

```bash
# yudao-ui-admin-vue3/.env.local（本地环境）
# 或 .env.production（生产环境）

VITE_UPLOAD_TYPE=client      # ← 改成 client，即前端直传模式
                             #   server = 传统经过后端
```

**④ 测试**

去 [基础设施 → 文件管理 → 文件列表] 上传一个文件，看网络请求 —— 你会发现请求直接打到了七牛云域名，后端只有一条 `presigned-url` 的小请求。

### 3.3 背后的原理：预签名 URL

```java
// FileController.java
@GetMapping("/presigned-url")
@Operation(summary = "获取文件预签名地址")
public CommonResult<FilePresignedUrlRespVO> getFilePresignedUrl(
        @RequestParam("path") String path) {
    return success(fileService.getFilePresignedUrl(path));
}
```

**什么是预签名 URL？**

就是后端用 `accessKey/accessSecret` 生成的一个**带签名的临时上传链接**，里面包含了：
- 允许上传到哪个 bucket、哪个路径
- 有效期（比如 5 分钟）
- 签名（用密钥算出来的，别人伪造不了）

前端拿到这个 URL 后，**直接 PUT 文件到这个地址**，S3 验签通过就存下。

```
① 前端：老板，我要传 report.xlsx，给我个通行证
② 后端：用密钥签名 → 生成一个 5 分钟有效的 URL → 返回给前端
③ 前端：拿着 URL 直接 PUT 文件到 S3
④ S3：验签 → 通过 → 存下
⑤ 前端：传完了，告诉后端"存好了，路径是 xxx"（后端写 infra_file 表记一笔）
```

💡 **安全要点**：密钥**永远不会暴露给前端**。前端拿到的是"一次性通行证"，不是钥匙。

### 3.4 代码实现位置

- **前端**：`src/components/UploadFile/src/useUpload.ts`
- **后端**：`FileController` 的 `/presigned-url` 接口

## 四、踩坑清单

| # | 坑 | 症状 | 解法 |
|---|---|---|---|
| 1 | Bucket 没设公共读 | 上传成功但 URL 打不开（403） | 云控制台把 Bucket 设为**公共读** |
| 2 | 没配 CORS | 前端直传报跨域错误 | 云控制台配跨域规则 |
| 3 | 用了本地磁盘 + 多台服务器 | 文件上传后访问 404 | 换 S3 或数据库存储 |
| 4 | 文件名用原始文件名 | 重名覆盖、中文乱码 | 芋道已用 UUID 重命名，别自己改 |
| 5 | 大文件用 `byte[]` 全读进内存 | OOM | 芋道 `FileClient.upload(byte[])` 就是全内存的，**超大文件要自己改成分片上传** |
| 6 | 敏感文件用了 `@PermitAll` 下载接口 | 谁都能下载 | 换 S3 + 私有 Bucket + 临时访问链接 |
| 7 | 生产环境用了官方公开的测试 key | 某天突然全部 401 | 自己申请云存储账号 |
| 8 | 换云厂商要改代码 | — | 用 S3 协议就不用改，只改配置（节点地址 + key） |

### 补充：关于大文件

⚠️ 芋道的 `FileClient.upload(byte[] content, String path)` 接收的是**完整字节数组**。

这意味着 100MB 的文件 = 100MB 内存。**别用它传视频**。

真要传大文件，需要自己实现**分片上传**（前端切片 → 逐个上传 → 后端合并），或者直接用云厂商的 SDK 做分片。

### 💡 自定义域名的好处

官方建议：*"最好使用自定义域名，方便迁移到不同的云存储服务。"*

```
不用自定义域名：https://ruoyi-vue-pro.s3.cn-south-1.qiniucs.com/xxx.jpg
                                    ↑ 七牛的域名，换云就全失效
用自定义域名：  https://cdn.yourcompany.com/xxx.jpg
                    ↑ 你自己的域名，换云只改 CNAME 解析，数据库里的 URL 全不变
```

**这是血泪经验**：如果一开始没用自定义域名，等你要从七牛迁到阿里云时，数据库里几百万条 URL 全得改。

## 五、一句话总结

**文件上传用 `fileService.createFile()` / `fileApi.createFile()`，存储选 S3 协议对象存储（MinIO 或云服务），生产环境强烈建议开「前端直传」（改 `VITE_UPLOAD_TYPE=client`）避免文件流量打满后端带宽。记住：Bucket 要公共读、要配 CORS、要用自定义域名。**
