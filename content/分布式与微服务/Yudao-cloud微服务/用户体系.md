# 用户体系（两类用户 + 四种登录方式）

> **一句话概括**：芋道把用户分成**管理员**（后台）和**会员**（App）两套，各用各的表；登录支持**账号密码 / 手机验证码 / 三方登录 / 微信小程序一键登录**四种方式，最终都换回同一个 Token。

---

## 零、先建立整体印象：一栋楼的两种人

> 🧒 **费曼第 1 段 · 5 岁小孩也能懂**

一栋写字楼里有两类人：

| | 员工 | 访客 |
|---|---|---|
| 谁 | 公司自己人 | 来办事的客户 |
| 从哪进 | 员工通道（刷工牌） | 前台登记 |
| 能去哪 | 办公区、档案室 | 接待区、会议室 |
| 信息 | 工号、部门、岗位 | 手机号、昵称 |

你会给他们发**同一种通行证**吗？不会 —— 因为需要的信息完全不一样。

芋道也是这个思路：

| | **AdminUser 管理员** | **MemberUser 会员** |
|---|---|---|
| 谁用 | 公司员工 | C 端客户 |
| 前端 | `yudao-ui-admin-vue3` 管理后台 | `yudao-ui-user` 用户 App |
| 接口 | `/admin-api/**` | `/app-api/**` |
| 数据表 | `system_users` | `member_user` |
| 特有字段 | `dept_id`（部门）、`post_ids`（岗位） | 手机号、会员等级、积分 |
| 默认权限 | **必须登录** | **无需登录**（浏览用） |

## 一、原理篇

### 1.1 为什么用两张表，而不是一张表加 `type` 字段？⭐

这是**数据库设计的经典争论**。官方给了明确回答：

> **官方原话**：
> > "确实可以采用统一用户表 + `type` 字段区分的方案……**不过实际项目中，不同类型的用户往往是不同的团队维护**，并且这也是绝大多数团队的实践，所以我们采用了多个用户表的方案。"

| | 一张表 + type | 多张表（芋道选择） |
|---|---|---|
| 优点 | 统一认证逻辑简单 | ✅ **字段职责清晰**、不同团队独立维护、权限隔离彻底 |
| 缺点 | ❌ 字段大量冗余（管理员不需要积分，会员不需要部门） | 认证要区分类型 |

> 💡 **关键判断依据**：如果两类用户**字段差异大 + 由不同团队维护 + 生命周期独立** → **拆表**。如果只是同一个系统的不同角色 → 用 `type`。

### 1.2 怎么区分？`user_type` 字段

有些表（如 `system_oauth2_access_token` 访问令牌表）需要同时关联两类用户，就用 `user_type` 字段区分：

```java
public enum UserTypeEnum {
    ADMIN(1, "管理员"),      // system_users
    MEMBER(2, "会员"),       // member_user
}
```

### 1.3 如何获取当前登录用户？

统一用 `SecurityFrameworkUtils` 工具类：

```java
// ① 获取当前登录用户（最全）
LoginUser loginUser = SecurityFrameworkUtils.getLoginUser();

// ② 获取当前用户编号（最常用）⭐
Long userId = SecurityFrameworkUtils.getLoginUserId();

// ③ 获取当前用户昵称（仅管理员）
String nickname = SecurityFrameworkUtils.getLoginUserNickname();

// ④ 获取当前用户部门ID（仅管理员）
Long deptId = SecurityFrameworkUtils.getLoginUserDeptId();
```

> ⚠️ **注意**：`getLoginUserNickname()` 和 `getLoginUserDeptId()` **只适合 AdminUser**，因为 MemberUser 没有部门和昵称概念。

**想获取更多信息怎么办？**（比如手机号、性别）

两步：
1. 在 `OAuth2TokenServiceImpl` 的 `#buildUserInfo(...)` 方法里，补充读取字段
2. 在 `SecurityFrameworkUtils` 里新增对应的 `getXxx()` 静态方法

## 二、应用篇：四种登录方式

### 2.1 方式一：账号密码登录

| | 管理后台 | 用户 App |
|---|---|---|
| 凭证 | **username 账号** + password | **mobile 手机号** + password |
| 接口 | `/admin-api/system/auth/login` | `/app-api/member/auth/login` |

```java
@PostMapping("/login")
@Operation(summary = "使用账号密码登录")
public CommonResult<AuthLoginRespVO> login(@RequestBody @Valid AuthLoginReqVO reqVO) {
    String token = authService.login(reqVO, getClientIP(), getUserAgent());
    return success(AuthLoginRespVO.builder().token(token).build());
}
```

> 💡 注意入参里带了 **IP 和 UserAgent** —— 用于记录登录日志、异地登录检测。

### 2.2 方式二：手机验证码登录

两步走：

```java
// ① 发送验证码
@PostMapping("/send-sms-code")
public CommonResult<Boolean> sendSmsCode(@RequestBody @Valid AuthSendSmsReqVO reqVO) {
    authService.sendSmsCode(getLoginUserId(), reqVO);
    return success(true);
}

// ② 用手机号 + 验证码登录
@PostMapping("/sms-login")
public CommonResult<AuthLoginRespVO> smsLogin(@RequestBody @Valid AuthSmsLoginReqVO reqVO) {
    String token = authService.smsLogin(reqVO, getClientIP(), getUserAgent());
    return success(AuthLoginRespVO.builder().token(token).build());
}
```

> 💡 **隐藏功能（App 端）**：如果用户未注册，**自动用手机号注册**！
> 所以 `/app-api/member/auth/sms-login` 接口**同时具备登录 + 注册功能**。这是 C 端产品的标准做法（降低注册门槛）。

> ⚠️ **安全提醒**：短信接口必须加**限流**！否则被人刷短信，一夜之间烧掉几万块。见 [[请求限流 RateLimiter]]。

### 2.3 方式三：三方登录（微信/钉钉等）

三步走：

```java
// ① 获取第三方授权跳转地址
@GetMapping("/social-auth-redirect")
public CommonResult<String> socialAuthRedirect(@RequestParam("type") Integer type,
                                               @RequestParam("redirectUri") String redirectUri) {
    return success(socialUserService.getAuthorizeUrl(type, redirectUri));
}

// ② 用 code 授权码快捷登录
@PostMapping("/social-login")
public CommonResult<AuthLoginRespVO> socialQuickLogin(@RequestBody @Valid AuthSocialQuickLoginReqVO reqVO) {
    String token = authService.socialLogin(reqVO, getClientIP(), getUserAgent());
    return success(AuthLoginRespVO.builder().token(token).build());
}

// ③ 绑定已有账号：调登录接口时额外带 socialType + socialCode + socialState 参数
```

详见 [[三方登录]]、[[OAuth 2.0（SSO 单点登录）]]。

### 2.4 方式四：微信小程序一键登录（App 端特有）⭐

```java
@PostMapping("/weixin-mini-app-login")
@Operation(summary = "微信小程序的一键登录")
public CommonResult<AppAuthLoginRespVO> weixinMiniAppLogin(
        @RequestBody @Valid AppAuthWeixinMiniAppLoginReqVO reqVO) {
    return success(authService.weixinMiniAppLogin(reqVO));
}
```

入参是 `phoneCode` + `loginCode`：
- `loginCode` → 换取 openid（用户身份）
- `phoneCode` → 换取手机号

**用户体验最好**（不用输手机号、不用收验证码），是小程序的主流登录方式。

## 三、其他功能

### 3.1 注册

| | 管理后台 | 用户 App |
|---|---|---|
| 是否支持注册 | ❌ **不支持**（管理员由系统创建） | ✅ 手机验证码登录时自动注册 |
| 接口 | `/admin-api/system/user/create` | `/app-api/member/auth/sms-login` |

```java
// 管理后台：由管理员在后台添加用户
@PostMapping("/create")
@PreAuthorize("@ss.hasPermission('system:user:create')")
public CommonResult<Long> createUser(@Valid @RequestBody UserCreateReqVO reqVO) {
    return success(userService.createUser(reqVO));
}
```

> 💡 **为什么后台不支持注册？** 因为管理员账号有高权限，开放注册是**严重安全漏洞**。这是正确的设计。

### 3.2 登出

**原理**：删除 Token（而不是前端删 localStorage 就完事）。

| 用户类型 | 接口 |
|---|---|
| 管理员 | `/admin-api/system/logout` |
| 会员 | `/app-api/member/logout` |

> 💡 这正是 [[功能权限]] 里说的"**为什么不用 JWT**"的体现 —— 有状态 Token 才能真正做到登出即失效。

## 四、进阶篇

### 4.1 四种登录方式对比

| 方式 | 体验 | 安全 | 成本 | 适合 |
|---|---|---|---|---|
| 账号密码 | 一般 | ⭐⭐⭐ | 无 | 后台管理系统 |
| 手机验证码 | 好 | ⭐⭐⭐⭐ | **每条短信要钱** | C 端 App |
| 三方登录 | 很好 | ⭐⭐⭐⭐ | 无 | C 端 App |
| 小程序一键登录 | **最好** | ⭐⭐⭐⭐ | 无 | 微信小程序 |

### 4.2 生产环境 6 个坑

| 坑 | 现象 | 解决 |
|---|---|---|
| **短信被刷** | 一夜之间几万块短信费 | ① 限流（IP + 手机号维度）② 图形验证码前置 ③ 单手机号每日上限 |
| **密码明文存储** | 数据库泄露 = 全站沦陷 | 必须用 **BCrypt** 加盐哈希（芋道已用） |
| **登录接口被暴力破解** | 撞库攻击 | 失败次数限制 + 验证码 + IP 封禁 |
| **Token 被盗** | 别人拿到 Token 就能操作 | HTTPS + Token 短期有效 + 敏感操作二次验证 |
| **异地登录不提醒** | 账号被盗都不知道 | 记录 IP/UA，异地登录发通知 |
| **会员表和管理员表 ID 撞车** | 关联查询查错人 | ⚠️ **必须同时用 `user_type` + `user_id`** |

### 4.3 双表设计的注意事项

```java
// ❌ 错误：只存 userId，不知道是哪个表的
private Long userId;

// ✅ 正确：user_type + user_id 组合
private Integer userType;    // 1=管理员 2=会员
private Long userId;
```

> ⚠️ 这是双表设计**最容易出 bug 的地方**：管理员 ID=1 和会员 ID=1 是**两个不同的人**，只靠 userId 关联必然出错。

## 四、一句话总结

| 问题 | 答案 |
|---|---|
| 有几种用户 | 2 种：AdminUser（后台）/ MemberUser（App） |
| 为什么分表 | 字段差异大 + **不同团队维护** + 权限隔离 |
| 怎么区分 | `user_type` 字段（1=管理员，2=会员） |
| 获取当前用户 | `SecurityFrameworkUtils.getLoginUserId()` |
| 四种登录 | 账号密码 / 手机验证码 / 三方登录 / 小程序一键登录 |
| 隐藏功能 | App 端短信登录**未注册自动注册** |
| 最大坑 | **只存 userId 不存 userType** → 关联查询查错人 |
