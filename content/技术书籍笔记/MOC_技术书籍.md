# 📚 MOC · 技术书籍笔记（Java / 计算机）

>
> 与已有笔记的分工：**技术库正文**（01~35 号）讲「这么做」；**书籍笔记**讲「为什么经典书籍这么规定，背后的原则是什么」。两者交叉引用，互为补充。

## 一、为什么单独建这一层

技术库正文（`01_技术库_Java开发/01_Java基础` 等）是**按技术点**组织的（JVM、JUC、MySQL……），偏「工具手册」。
书籍笔记是**按书**组织的，偏「**方法论与心法**」——它们回答的是另一类问题：

| 你遇到的困惑 | 该翻哪一层 |
| ---- | ---- |
| 「这个 API 怎么用」 | 技术库正文 |
| 「为什么大家说这么写不好」 | **书籍笔记（原则层）** |
| 「线上 OOM 怎么查」 | 正文 [[02_JVM 原理与调优]] |
| 「JVM 为什么这么设计、收集器演进背后的权衡」 | **书籍笔记 [[《深入理解Java虚拟机》笔记]]** |
| 「代码能跑但被 review 打回，说不够整洁」 | **书籍笔记 [[《代码整洁之道》笔记]]** |
| 「怎么把一坨烂代码安全地改好」 | **书籍笔记 [[《重构》笔记]]** |

### 2.1 工程素养 · 怎么写好代码

### 2.2 底层原理 · Java 与 JVM

| 书籍 | 一句话核心 | 笔记 |
| ---- | ---- | ---- |
| **《深入理解 Java 虚拟机》**<br>周志明 | **JVM 的「为什么」**——内存结构、GC 算法与收集器演进、字节码、类加载、JIT 编译优化 | [[《深入理解Java虚拟机》笔记]] ⭐ |
| **《Java 性能权威指南》**<br>Scott Oaks | **性能的「怎么做」**——从 JIT 到 GC 到线程池到数据库的端到端调优 | [[《Java性能权威指南》笔记]] |

> 💡 **搭配阅读**：底层原理两本 + 正文 [[02_JVM 原理与调优]]（实战手册）→ 形成「为什么 → 怎么做 → 出事怎么查」的完整闭环。

### 2.3 计算机基础 · 万变不离其宗

| 书籍 | 一句话核心 | 笔记 |
| ---- | ---- | ---- |
| **《计算机组成原理》**（唐朔飞/王道） | **CPU 怎么取指执行、内存层次为什么这样设计**——一切性能问题的物理根源 | [[《计算机组成原理》笔记]] |
| **《操作系统》**（汤小丹/王道） | **进程线程、内存管理、IO 模型**——Java 并发与 NIO 的地基 | [[《操作系统》笔记]] |

> 💡 **为什么后端要读这两本**：`volatile` 的内存屏障、`MESI` 缓存一致性、零拷贝、epoll、页表——**这些「高大上」的词，答案都在计算机基础里**。

## 三、阅读路线（按需选，别硬啃）

### 路线 A：新人打地基（0~1 年）

```
《代码整洁之道》前 9 章   →  立刻改变你的代码习惯（收益最快）
        ↓
《Effective Java》        →  补上 Java 语言的正确姿势
        ↓
《重构》                  →  学会安全地改别人的烂代码
        ↓
《深入理解 Java 虚拟机》  →  开始理解「为什么」
```

### 路线 B：中级突破（1~3 年）

```
《深入理解 Java 虚拟机》  →  打通 JVM 底层
        ↓
《Java 性能权威指南》     →  把性能从「玄学」变成「测量」
        ↓
《操作系统》 + 计算机组成 →  补计算机基础，理解并发/NIO 的地基
        ↓
回头重读《重构》          →  带着真实项目经验重读，理解完全不同
```

### 路线 C：只解决眼前问题（速查）

| 你的问题 | 直接看 |
| ---- | ---- |
| 命名想不好、函数太长 | [[《代码整洁之道》笔记]] §命名 / §函数 |
| 一堆 `if-else` 想改 | [[《重构》笔记]] §坏味道与手法 |
| `equals`/`hashCode` 老写错 | [[《Effective Java》笔记]] §对象通用方法 |
| 线上 GC 频繁 | [[《深入理解Java虚拟机》笔记]] §GC + 正文 [[02_JVM 原理与调优]] |
| 线程池参数怎么定 | [[《Java性能权威指南》笔记]] §线程与同步 |
| `volatile` 为什么能保证可见性 | [[《操作系统》笔记]] §内存管理与缓存一致性 |
