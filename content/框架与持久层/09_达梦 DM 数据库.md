# 达梦 DM 数据库（原理 → 应用 → 进阶）

> **一句话概括**：达梦是"国产版的 Oracle"——语法像 Oracle、概念像 Oracle、用法也像 Oracle。**如果你只会 MySQL，切到达梦就像从普通话区搬到粤语区**，大部分东西名字不一样、写法不一样，但本质还是关系型数据库那套。
>
> **适合谁**：项目里突然要接达梦（信创要求），或者面试被问到"国产数据库和 MySQL 有什么区别"的人。
> **怎么读**：应用篇的对照表是核心，建议先快速扫一遍"哪里不一样"，再回头读原理和坑。

---

## 零、先建立整体印象：把它想象成"方言翻译"

你是一位在北方（MySQL 区）长大的程序员，突然被派到南方（达梦/Oracle 区）做项目。两边的数据库都能存数据、都能查表，但**日常用语完全不同**：

| 场景 | MySQL（普通话） | 达梦 DM（粤语） | 一句话解释 |
|---|---|---|---|
| 自增 ID | `AUTO_INCREMENT` | `SEQUENCE` + 触发器 / `IDENTITY` | 达梦没有"自动递增"这个概念，要么用序列号发号器，要么用兼容模式的 IDENTITY |
| 分页查数据 | `LIMIT 10 OFFSET 20` | `ROWNUM` / `FETCH FIRST` | 达梦更接近 Oracle 的分页写法，LIMIT 不存在 |
| 字符串拼接 | `CONCAT(a, b)` | `a \|\| b` | 竖线拼接是 Oracle 系的习惯 |
| 查伪列 | `SELECT 1` | `SELECT 1 FROM dual` | 达梦和 Oracle 一样，需要一张"假表"dual |
| 字段引号 | 反引号 `` `name` `` | 双引号 `"name"` | 双引号在达梦里是"区分大小写"的意思，和 MySQL 不同 |
| 当前时间 | `NOW()` | `SYSDATE` | Oracle 系函数 |

**记住这个对照表，后面每写一条 SQL 都来查一下。**

## 一、原理篇：达梦是什么，为什么突然要用它

### 1.1 达梦的定位

- **国产关系型数据库**，信创（信息技术应用创新）背景下的主流选择之一
- **高度兼容 Oracle**：语法、函数、系统视图、PL/SQL 都尽量贴近 Oracle，不是 MySQL 系
- **实例 + 表空间模型**：一个数据库实例可以挂多个表空间；用户和模式（Schema）体系也近 Oracle
- **简历里的真实场景**：资本风险合同管理系统、小微风控系统，技术栈都是 `DM + MyBatis-Plus`

> 💡 **为什么信创要换数据库？** 简单说是"自主可控"——核心系统用的底层软件要逐步换成国产的。达梦、人大金仓、OceanBase 都是这个背景下的产物。对开发者来说，**面试时知道"达梦兼容 Oracle"这句话就够了**。

### 1.2 达梦 vs MySQL vs Oracle：一张表说清关系

| | MySQL | 达梦 DM | Oracle |
|---|---|---|---|
| 语法风格 | 简洁、灵活 | **近 Oracle** | 最严格、功能最全 |
| 自增 | `AUTO_INCREMENT` | `SEQUENCE` / `IDENTITY` | `SEQUENCE` |
| 分页 | `LIMIT` | `ROWNUM` | `ROWNUM` |
| 字符串拼接 | `CONCAT` | `\|\|` | `\|\|` |
| 大小写敏感 | 默认不敏感（Linux 下表名敏感） | **默认敏感**（加双引号才区分） | 默认不敏感（加双引号区分） |
| 空字符串与 NULL | `'' != NULL` | **空字符串 = NULL**（Oracle 习惯） | `'' = NULL` |
| 驱动类 | `com.mysql.cj.jdbc.Driver` | `dm.jdbc.driver.DmDriver` | `oracle.jdbc.OracleDriver` |

> ⚠️ **空字符串 = NULL 是个大坑**：MySQL 里 `''` 和 `NULL` 是两回事，达梦里 `''` 就是 `NULL`。如果你代码里用 `WHERE name != ''` 来过滤空值，到达梦里会查不到任何结果——因为空字符串不存在，全是 NULL。

## 二、应用篇：MySQL 用户切到达梦，日常写法怎么变

### 2.1 自增主键（最常用，必须会）

**MySQL 写法（一行搞定）**：
```sql
CREATE TABLE orders (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100)
);
```

**达梦写法（两种路线）**：

**路线 A：序列 + 触发器（最像 Oracle，也最常用）**
```sql
-- ① 先建一个"发号器"（序列），从 1 开始，每次加 1
CREATE SEQUENCE seq_order START WITH 1 INCREMENT BY 1;

-- ② 再建一个触发器：每次插入前，如果 id 没填，就自动去序列里取下一个号
CREATE OR REPLACE TRIGGER trg_order
BEFORE INSERT ON orders FOR EACH ROW    -- 在插入之前，对每一行触发
BEGIN
    IF :NEW.id IS NULL THEN               -- 如果用户没给 id
        :NEW.id := seq_order.NEXTVAL;     -- 用序列的下一个值填上
    END IF;
END;
```
> 💡 这就是达梦和 MySQL 最大的不同：MySQL 的 `AUTO_INCREMENT` 是"表自带"的；达梦的 `SEQUENCE` 是"独立的发号器"，可以给多张表共用，也可以单独调用 `seq_order.NEXTVAL` 取号。

**路线 B：IDENTITY（更简洁，达梦兼容模式支持）**
```sql
CREATE TABLE orders (
    id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name VARCHAR(100)
);
```
> 💡 如果项目是从 MySQL 迁移来的，用 IDENTITY 改动最小；如果是全新达梦项目，用 SEQUENCE 更灵活（可以跨表共用、可以批量预取）。

### 2.2 分页查询

**MySQL**：
```sql
SELECT * FROM orders ORDER BY id DESC LIMIT 10 OFFSET 20;
-- 从第 21 条开始，取 10 条
```

**达梦**：
```sql
-- 写法一：用 ROWNUM（Oracle 经典写法，但注意 ROWNUM 是在结果生成时分配的）
SELECT * FROM (
    SELECT t.*, ROWNUM AS rn FROM (
        SELECT * FROM orders ORDER BY id DESC
    ) t WHERE ROWNUM <= 30      -- 先取前 30 条（包含 1~30）
) WHERE rn > 20;                 -- 再过滤掉前 20 条，剩下 21~30

-- 写法二：用 FETCH FIRST（达梦 8 支持，更直观）
SELECT * FROM orders ORDER BY id DESC OFFSET 20 ROWS FETCH FIRST 10 ROWS ONLY;
```
> ⚠️ **MyBatis-Plus 分页插件**：必须告诉 MP "这是达梦"，让它生成达梦风格的分页 SQL。配 `DbType.DM`，否则 MP 默认生成 `LIMIT` 语法，达梦直接报语法错误。

### 2.3 其他日常差异速查

```sql
-- 字符串拼接
SELECT 'Hello' || ' World' FROM dual;     -- 达梦/Oracle：用 ||
-- SELECT CONCAT('Hello', ' World');       -- MySQL：用 CONCAT

-- 空值处理
SELECT NVL(name, '暂无') FROM users;      -- 达梦/Oracle：NVL
-- SELECT IFNULL(name, '暂无') FROM users; -- MySQL：IFNULL

-- 当前时间
SELECT SYSDATE FROM dual;                  -- 达梦/Oracle
-- SELECT NOW();                           -- MySQL

-- 长度
SELECT LENGTH(name) FROM users;            -- 达梦/Oracle：字节长度
SELECT CHAR_LENGTH(name) FROM users;       -- 达梦/Oracle：字符长度（中文算 1 个）
-- SELECT LENGTH(name);                    -- MySQL：字节长度；CHAR_LENGTH：字符长度
```

## 三、进阶篇：MyBatis-Plus 适配 + 迁移 + 常见坑

### 3.1 MyBatis-Plus 适配 checklist

| 配置项 | 注意点 |
|---|---|
| **主键策略** | `@TableId(type = IdType.AUTO)` 配合 SEQUENCE / IDENTITY；生成器里 `db-type=dm` |
| **分页插件** | `PaginationInnerInterceptor(DbType.DM)`，**必须用 DM 方言** |
| **逻辑删除** | 字段类型建议 `NUMBER(1)` 或 `CHAR(1)`，映射 `0/1`；确认 `@TableLogic` 在达梦下生效 |
| **多数据源** | 和 MySQL 混用时用 `dynamic-datasource`，按注解切换（见 [[06_MyBatis 与 MyBatis-Plus]]） |

### 3.2 迁移：从 MySQL 到达梦

1. **数据迁移**：用达梦自带的 **DTS 工具**（Data Transfer Service），支持从 MySQL/Oracle 导到达梦，表结构 + 数据都能迁
2. **SQL 改写清单**：
   - `LIMIT` → `ROWNUM` / `FETCH FIRST`
   - `AUTO_INCREMENT` → `SEQUENCE` + 触发器 / `IDENTITY`
   - `IFNULL` → `NVL`
   - `CONCAT` → `||`
   - `SELECT 1` → `SELECT 1 FROM dual`
   - 反引号 `` ` `` → 双引号 `"`（或去掉引号）
3. **函数差异**：`GROUP_CONCAT` → `WM_CONCAT` / `LISTAGG`；`FIND_IN_SET` 没有直接对应，需改写

### 3.3 达梦专属坑（踩过才知道）

1. **关键字敏感**：`user`、`order`、`comment`、`index` 等是达梦保留字，拿来做表名或字段名必须加双引号，否则报「语法错误」。**建议：干脆不用保留字当名字**，省去一堆引号麻烦。
2. **大小写敏感**：达梦**默认大小写敏感**，但**不加双引号时自动转大写**。所以 `CREATE TABLE user` 实际建的是 `USER`，你 `SELECT * FROM user` 能查到，但 `SELECT * FROM "user"` 反而查不到（因为 `"user"` 是小写，和 `USER` 不是同一个表）。
   > ✅ **统一约定**：全部用大写命名，或者全部不加双引号，让达梦自动转大写。不要混用。
3. **空字符串 = NULL**：前面说过，这是和 MySQL 最大的行为差异。代码里判断"非空"要用 `IS NOT NULL`，不能用 `!= ''`。
4. **驱动依赖**：Maven 依赖是 `com.dameng:DmJdbcDriver`，连接串 `jdbc:dm://host:5236/库名`，默认端口 5236。
5. **执行计划**：和 Oracle 一样用 `EXPLAIN`，关注是否走索引、是否有全表扫描。达梦的优化器逻辑近 Oracle，MySQL 的优化经验不完全适用。

> 💡 **面试一句话**："达梦高度兼容 Oracle，实例+表空间模型，和 MySQL 的主要差异在分页（ROWNUM）、自增（SEQUENCE）、空字符串（=NULL）、大小写敏感。项目里用 MyBatis-Plus 时需要配 DM 方言。"
